# 领域文档读取与维护

## 读取顺序

1. 探索代码前先读根 [GLOSSARY-MAP.md](../../GLOSSARY-MAP.md)，确定本次任务涉及的域。
2. 读取任务相关的 `docs/domains/<domain>/GLOSSARY.md`。沿术语链接、输入输出或本次接口变化补读依赖域；无需每次加载六份表。
3. 阅读 `docs/adr/` 中涉及本次范围的决策。首版布局见 [ADR-0001](../adr/0001-domain-glossary-layout.md)。

六域为采集、事实、研究、计算、报告和知识。代码可以跨越文档中的职责边界，实际定位使用地图的代码列。公司治理取证及重建先查事实域专项章节。

## 使用和维护术语

- Issue、方案、代码评审、测试命名和用户讨论使用所属域中的概念名称；提及快照、覆盖或完成状态时说明对象与范围。
- 每个概念在所属域定义一次，消费它的域使用相对链接。新增条目写清中文名、代码标识、含义、必要区分和当前依据。
- 字段、公式、枚举和版本约束引用对应契约、代码及机器配置，避免逐项复制。职责与数据范围以[项目总计划](../../项目总计划.md)为依据，当前能力和状态查相应代码、测试及运行证据。
- 遇到术语表、契约或实现不一致时，报告具体差异及其影响；已知含义可在当前授权范围内修正，未明确的语义保留待决项并向用户澄清。
- 改变术语含义时同步所属域及受影响的跨域引用；改变职责、数据语义或版本兼容策略时，追加相关 ADR 并说明取舍。
- 与现有 ADR 冲突时指出对应记录和原因，先确定是否需要重新决策。
