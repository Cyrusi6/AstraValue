# 更新实际值、假设与历史版本

用于 ES08.Q05 的通用研究指导。这里的案例全部是合成教学数据；正文不陈述任何目标公司的事实。

## 分析目标与适用条件

用追加版本保存原假设、来源和结果，分解新实际、假设调整及模型口径变化；这是项目复现约定，不是综述对具体软件流程的规定。

先核实业务性质、模型用途和所列口径；金融或行业专门路径按行业缺口处理。

## 输入与证据

- 新旧披露与取得时间、对应期间；映射待补，先确认期间、单位与归属范围。
- 原假设和新假设的变更理由；映射待补，先确认期间、单位与归属范围。
- 原模型版本、结果及逐项估值变化；映射待补，先确认期间、单位与归属范围。
- 关键输入、调整和假设的原文证据；需文档、页码及支持关系定位。

## 操作步骤

1. 为新财报、重大经营/融资事件、价格时点和关键假设失效设置复核触发，记录实际取得时间。
2. 先统一新旧期间、合并范围和指标定义，再以新披露替换对应实际项；其他未披露项继续留缺。
3. 按量价、利润率、再投资、融资/股本、风险/增长假设及模型更换展示估值变化桥接，避免将全部差异归为经营变化。
4. 生成新版本并保留旧版和修正说明；对照当时信息评估旧预测，不能以最新数据倒改历史预测准确率。

## 依据与推导边界

来源直接支持：倍数、增长、风险和现金流关系随时间变化，旧估计可能失去适用性；新增信息需要重新核查模型依据。
定位：SRC-NYU-VALUATION-SURVEY-2006@2006-11，PDF p59、73，time-varying valuation relationships。

项目综合：用追加版本保存原假设、来源和结果，分解新实际、假设调整及模型口径变化；这是项目复现约定，不是综述对具体软件流程的规定。
该综合的前提是原模型归属、现金流与风险口径一致。未把源文献未规定的软件和数据流程称为强制金融规则。

## 正常、反例与缺失案例

### normal — ES08.Q05.normal

合成输入：{"synthetic": true, "old_actual_revenue": 100, "new_actual_revenue": 110, "old_forecast_preserved": true, "new_assumptions_logged": true}
可支持：可复核实际更新及新假设影响，保留旧版。
不能支持：不能自动将收入增长全部归为估值提高。

### counterexample — ES08.Q05.counterexample

合成输入：{"synthetic": true, "original_forecast": 100, "new_actual": 80, "old_forecast_overwritten_as": 80}
可支持：历史预测被倒改，应恢复旧版并记录偏差。
不能支持：不能报告旧预测准确。

### missing — ES08.Q05.missing

合成输入：{"synthetic": true, "new_period": "quarter", "old_period": "full_year", "comparable_prior_period": null}
可支持：需补可比期间后再比较或明确局限。
不能支持：不能机械年度化后当已发生全年实际。

## 主要限制和行业待补

- 高频重新估值不自动提高准确性，只有相关新信息才构成重估依据。
- 历史复现不等于证明历史时点已能取得全部资料。
- 定量输入映射待补，不代表已能从事实库直接取数；方法不生成目标公司判断。
- 行业高频驱动阈值及事件影响路径待行业手册补充。
