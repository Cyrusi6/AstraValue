# OpenSpec 按任务读取上下文

本项目的 OpenSpec Skills 使用以下读取约定。完整规范仍是权威来源；精简的是每次进入模型上下文的内容，不是需求、依赖或验收标准。

## 读取顺序

1. **定位当前工作。** 从 CLI 的 `status` / `instructions` 获取根目录、schema、具体文件路径、状态和任务清单。先解析 JSON，再输出当前状态、路径和必要任务；不要反复展开已完成任务正文。返回的 `instruction`、`context` 和适用规则仍须完整考虑。
2. **读取共同约束。** 读取项目 context、变更目标和 Non-goals、跨任务不变量、兼容性与验收边界。对配置、proposal、design、tasks、specs 建立标题/约束索引，检查文件开头未归入标题的约束。不能只靠关键词命中就假定其他约束无关。
3. **选择当前任务及依赖。** 读取任务完整条目、所在小节说明、前置任务、直接相关的完整 Requirement（含全部 Scenario）、设计章节，以及必要代码和测试。追踪引用的主规格、共享契约和前置决策；依赖闭合后才开始实现。
4. **必要时扩大范围。** 涉及来源身份、时间/快照、共享接口、迁移、幂等、权限、兼容性或跨模块行为时，补读相关上下游约束。标题不明确、任务未链接规格、来源冲突或无法判定影响面时，扩大到相关文件全文；仍存在关键歧义再向用户澄清。
5. **按工作组继续。** 当前任务结束后，为下一组重新确定依赖。分组只改变读取顺序，不把“完成整个变更”的请求变成“只做一个任务”。不读取无关 change、archive、完整历史日志或原始数据来凑上下文。

文件较大时可先用 `rg -n '^#{1,6} ' <file>` 定位章节，用 `rg -n '^- \[ \]' <tasks-file>` 查看未完成任务；已完成任务先保留 ID、状态和分组，仅展开当前任务的前置条目。随后读取完整相关章节。索引只是导航：正文约束和场景仍需阅读。禁止简单截取前 N 行、按字数截断 Requirement，或因为预算不足省略失败行为。

## 复用与刷新

- 同一会话已经读取、仍可见且未变化的内容可以复用；每次恢复、切换任务组、编写依赖产物或执行最终验收前检查来源身份。
- 使用文件路径和 SHA-256（例如 `Get-FileHash -LiteralPath <path> -Algorithm SHA256`）核对配置、元数据、相关产物及读取过的来源；同时刷新 CLI 的文件集合，发现新增/删除文件。不能只用 Git HEAD 或修改时间，因为文件可能未提交。
- 文件、根目录、schema、任务范围或配置变化时，重新检查受影响章节和依赖。跨会话/上下文压缩后，即使哈希未变，正文已不在上下文也必须重新读取当前任务必需的原文；交接摘要不能代替契约。
- 不重复调用内容未变的 `instructions` 来回显同一模板。写入产物后仍要刷新 CLI status；切换操作、规则变化或进入最终验收时仍获取所需的当前指令。

## 各阶段的覆盖范围

| 操作 | 必需覆盖 |
| --- | --- |
| explore | 当前问题、共同约束及相关依赖；纯讨论不写交接文件 |
| propose | 当前产物、schema 前置依赖及相关项目证据；覆盖整个必需产物集合 |
| apply | 当前任务组及依赖；按用户授权范围连续推进 |
| update | 指定修改及双向受影响引用；要求整体协调时覆盖全部产物 |
| verify | 全变更的任务、Requirement、Scenario、设计决策和证据，可分组逐段完成，不能缩成当前任务审查 |
| sync | 全部选定 delta 及对应主规格；显式子集不能被扩大 |
| archive | 全部任务状态、适用验收证据和每项 delta 同步状态；实际移动前完成检查 |

## 交接记录与变更规模

需要跨会话续做的实施工作，在 CLI 返回的 `changeRoot` 下维护一份简短 `context.md`，格式见 [handoff.md](../.agents/skills/openspec-apply-change/references/handoff.md)。它是可失效的派生导航，不注册为 schema 必需产物，不成为第二份任务清单或阶段日志。只给实际正在工作的变更写记录，不批量给旧变更生成摘要。

新 change 尽量对应一个可独立验收的结果；新任务链接相关 Requirement、设计章节和前置任务，方便精确读取。已经批准的大变更不自动拆分、归档或删减；拆分前明确依赖和验收边界，并取得相应授权。

不改变 `openspec/config.yaml`、权威文档与 CLI 的约束效力。自动化测试、真实联网样本、人工黄金样本分别报告；摘要、OpenSpec strict、AI verify 和任务勾选都不能替代这些证据。
