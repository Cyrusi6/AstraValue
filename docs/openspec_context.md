# OpenSpec 上下文约定

- 使用 CLI 返回的根目录、schema 和具体路径。用户指定 store 时先确认其 ID，并在支持该参数的命令中保持 `--store <id>`。
- 当前根的 `context`、产物 `rules` 与实际 `instruction` 决定项目约束；操作 guidance 是补充建议，不替代状态或验收证据。
- 先读范围、共同约束和任务索引，再读当前工作相关的完整 Requirement/Scenario、设计及前置依赖。依赖不明或影响跨模块时扩大读取；不按字数截断契约，不默认加载无关变更和历史。
- 已读取、仍在上下文且未变化的内容可复用；恢复会话或相关文件变化时刷新必要原文。
- 不必每次切换任务都给上下文文件计算整套 SHA-256。普通续作检查相关文件变化即可；这不涉及业务数据的哈希证据链。
- 实施按任务读取并持续完成授权范围；完整 verify 仍须覆盖全部契约，sync/archive 仍须覆盖选定范围。
- 仅需跨会话交接时，简短记录当前任务、关键决定、阻塞和来源位置。不默认创建 `context.md`，不要求固定模板，交接记录不能替代原文。
- 完成标准沿用当前项目规则；自动化、真实数据与人工验收分别记录，不由任务勾选或 OpenSpec strict 相互替代。

这些规则只管理模型上下文，不改变业务数据的哈希与证据链。升级时审阅 `openspec update` 对本地 Skill 定制的覆盖。
