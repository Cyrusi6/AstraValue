## Context

范围与已确认决定见 [proposal.md](proposal.md)，行为合同见 [spec.md](specs/eight-step-knowledge-base/spec.md)。本文件是待审阅的实施设计草案，本轮不实施。

- [研究问题清单](../../../config/structured_data/research_requirements.v1.json)已有 54 题，八步题数分别为 10、10、6、6、6、5、6、5。问题集版本为 `1.0.0`，承载它的 registry 版本为 `1.1.0`，二者不可混用。
- [方法注册表](../../../src/analysis/registry.py)可读取方法和文档、构建带哈希的包；其文档读取未按内容成熟度筛选。
- [方法库说明](../../../docs/methodology/README.md)明确正文仍为骨架。现有结构一致性校验不检查重要规则是否得到来源支持。
- 本知识服务不依赖事实物化分支已完成或生产采集可用，测试不需要读取公司数据库。

## Goals / Non-Goals

**Goals:** 在既有方法资产上增加按问题读取、内容发布与完整版本复现能力；以行为测试和有依据的案例分别验证程序与知识内容。

**Non-Goals:** 不改原财务计算、数据消费和报告冻结约定；不为首版引入新数据库、前端、开放式自然语言检索或自动生成公司结论的流程。

## Decisions

### D1 单一内容权威与可重建索引

方法正文继续在 `docs/methodology/` 维护；知识映射、来源元数据、成熟度及发布清单位于 `config/methods/` 下的新增知识配置，金融计算公式仍由原计算配置和实现负责。知识条目通过稳定标识引用原 `method_id`，需要多个细粒度知识条目时可共同引用一个原方法，不强制 54 题等于 54 篇文档。

54 题直接读取原清单。新增配置仅保存问题编号到知识条目及步骤关系的映射，不复制维护问题标题。检索索引和结构化结果由正文与配置生成，不能成为第二个可独立编辑的金融规则来源。

定量输入优先绑定 [metrics.json](../../../config/methods/metrics.json) 中的指标，并与[问题需求清单](../../../config/structured_data/research_requirements.v1.json)中的证据需求标识关联，保存所引用定义的版本或内容身份。方法自身规定所需期间、单位和合并范围；如果现有定义不足以证明匹配，返回映射待补，不能把名称相近当成语义相同。涉及派生量时引用现有公式/方法版本，不在知识入口重复计算。原文证据保存查找主题、所需定位及支持关系，不强造 `metric_id`。本变更不自动补数据、不修改旧计算口径；发现旧定义与研究依据有冲突时登记差异及受限用途。

方法内容已可用与数据已能自动取得是不同维度。未映射的概念可保留完整理论指导并明确限制，但不宣称已可直接取数；首版 54 题通用覆盖不冒充公司数据就绪率。

选择本地文件与确定性映射，是因为首版问题集合明确；向量检索和图数据库可在后续确有检索需求时增加，不作为此次依赖。

### D2 读取合同与状态分离

首版提供独立的本地读取入口及命令行 JSON 输出，供 Agent 调用；参数包括 `question_id`、可选选择上下文、可选知识版本标识、读取层次及显式草稿/候选预览。接口名称和命令拼写在测试建立时确定，不改变既有 HTTP API。

默认返回结构化操作指导，包括问题身份、所用条目及版本、用途和执行顺序、关键证据及输入绑定、主要反例、适用限制、待补上下文/缺口和详细读取引用。Agent 按引用展开完整步骤、案例或来源。短结果由同一条目中已审阅的操作要点确定性生成，不在每次请求时让模型另写一套可能漂移的摘要。

展开引用携带知识包与条目版本，发布新版不会改变旧引用的结果。若长度限制无法保留全部必要指导，返回明确的不完整状态、未返回部分及继续读取引用，不能把删掉重要限制的结果视为完整。未知问题、不存在版本、配置错误和已知问题内容待补分别返回可区分状态。

条目成熟度与包发布范围也分开：首批候选包可包含已达到条目发布条件并固定版本的方法，但必须显式指定候选版本试用，不成为完整首版默认包。覆盖检查始终标明所检查的包；完整默认发布前可对候选包执行全部验收，因此不存在“先设默认才能验收、先验收才能设默认”的依赖环。此前没有默认包时返回尚无完整发布及缺口；不能为方便试用而冒充默认全量可用。

以下维度分别表示，不压成单一“完成度”：

| 维度 | 含义 |
|---|---|
| 问题映射 | 是否有有效问题到知识条目的关联 |
| 通用内容覆盖 | 本题有实质步骤的通用路径是否已发布 |
| 行业补充 | 本题还有哪些行业专用变量、解释或模型未建设 |
| 内容成熟度 | 骨架、草稿、已审阅、已发布，以及已发布版本的后续撤回提示 |
| 当前适用性 | 适用、不适用、尚需上下文确认 |
| 输入绑定 | 定量指标已匹配、映射待补，或需定位的原文证据 |

例如银行场景下普通营运资本方法不适用，不代表该方法正文未完成；缺行业上下文也不等于方法不存在。

### D3 来源、案例和发布

条目中的关键规则有稳定规则编号，逐条关联来源位置；正文引用来源编号，原始来源元数据集中维护。来源类型至少区分正式规则、原始研究/教材、专业分析及项目综合解释。记录实际可核查范围，不按网页数量机械判断可靠程度。

研究先取得资料与依据，再独立设计案例预期；这些准备材料不直接变成已发布方法。每个方法的案例集至少包含正常案例、反例及适用的缺失/边界情况。预期标准记录应识别因素、可支持判断、禁止的越界推断、理由与来源，以及执行评测的方式。例子可用明确标注的合成数据，不冒充真实公司案例。

| 验证方式 | 能检查什么 | 不能据此声称什么 |
|---|---|---|
| 程序断言 | 引用可解析、定义匹配、内容身份、审阅对象版本、字段/状态、固定数值案例及已定义关系约束 | 不能仅凭 `approved` 字段或关键词齐全断定来源支持、反例有效 |
| 内容审阅 | 依据是否支持规则、步骤是否成立、反例是否展示误判、定性预期是否合理 | 不用单一模型分数替代理由及最终人工抽查 |
| 外部 Agent 案例 | 读取并应用指导时是否识别预期支持关系、限制和缺口 | 不等于知识库开始接收公司事实或生成公司判断 |

内容审阅记录固定案例/方法/来源版本、判定标准、执行者类型、结论和逐项理由。模型参与时记录使用的模型及评测提示版本；有争议的判断保留待解决状态。必须用结构不变的错误样本检查评测标准：反转重要规则、换成不支持规则的来源、删除关键反例。仅验证发布校验器能拒绝过期审阅记录还不够，内容审阅本身也需按预先标准指出这些错误。定性结果不要求逐字一致。

采用配对案例，一组有足以支持预期推断的证据，一组仅缺少关键证据，检查合理使用与限制判断两种能力，防止通过统一拒答获得虚假通过。样例事实只进入外部评测，不作为知识查询参数。

发布记录关联固定版本的来源核查、结构检查、案例审阅及未解决事项。程序、Agent 审阅和人工抽查分别记录，不强制用户逐条批准每一张卡；首版整体仍保留 K08 的人工内容抽查门槛。草稿及局部候选包可显式预览，默认读取只消费完整默认包中的有效已发布版本。

来源原文及取得快照按现有本地研究资料规则保存，不把有再分发限制的材料放进 Git；可发布的整理正文、引用定位及核查记录可纳入版本控制。没有合适权威依据时保留草稿及具体缺口，不为了达到 54/54 填造规则。

### D4 发布快照与兼容性

采用可追加的知识发布包，固定问题集、映射、方法正文、输入指标定义、来源定位和审阅对象的内容身份。发布包包含恢复旧结果所需的规范化内容或不可变内容引用；哈希只做完整性检查，不能用哈希替代被覆盖的旧正文或指标定义。源文档后续编辑不改变已有发布包。

版本更正以新包和撤回/替代元数据追加，历史读取保留原内容。按版本读取不触发重新检索外网，也不因外网来源暂时不可用而悄悄改用另一版。无版本请求使用当前有效完整发布包，并应用已有更正/待复查提示。

从来源依据、指标定义、规则、方法、问题及案例引用构建可重建的反向索引，不新增图数据库。输入为维护时登记的实际更正或版本变动；先输出受影响对象及原因，再对影响当前内容的对象追加待复查记录。未解决对象暂停默认推荐，未受影响方法继续可用。历史曾发布数和当前有效通用路径覆盖分别统计；唯一方法失效时当前覆盖下降，有其他完整有效路径时才保持覆盖并说明替代关系。收到更正之后，即便默认包原先曾达到 54/54，当前完整验收也应如实反映受影响的不可推荐内容。

审阅有效性绑定方法正文及其证据、输入定义的内容身份，不能给新版沿用旧版通过标记。重新审阅与发布形成新记录，历史包保持不变，复核读取附上当前已知更正提示。来源页面无关版式变化不直接推断规则错误，先登记具体影响；本变更不添加自动外网监控。

新增知识适配层独立判断内容成熟度，保留 `MethodRegistry.get()` 等原计算入口约定，不在本变更修改旧报告。知识版本包与原计算 `MethodBundle` 分开标识并可互相引用；报告实际接入知识版本固定属于后续消费方改动，不在此变更擅自添加报告字段。

### D5 TDD 顺序与验证

1. 固定 K01—K08 与判定标准，建立需求—场景—验证方式映射。
2. 先选 `ES01.Q10`（定价权）、`ES02.Q04`（ROIC 口径）、`ES02.Q08`（营运资本适用性）三个代表问题研究来源和案例，再写覆盖它们所需的最小读取、绑定、短结果、候选包及版本测试并观察失败。
3. 只实现样例需要的最小能力，完成三个问题的通用指导，明确各题尚余内容。固定候选版本并让 Agent 试用；反转规则、错换来源和配对案例检查同时执行。试用发现的问题先补测试修正，不能把候选样例局部路径当成整题已完成。
4. 完善剩余发布、变更影响及兼容能力，再按题逐批扩展正文。每个切片先红后绿，已完成能力保持回归通过；纯文字润色无行为变化时不机械新增测试。
5. 最后运行 54 题完整验收、八步各至少一个 Agent 样例和人工内容抽查；任何分项未完成保持对应缺口，不以候选包通过替代完整首版。

测试入口分开安排：

| 入口 | 预期用途与结果 |
|---|---|
| `tests/knowledge/regression/` | 当前切片和所有已交付能力的日常回归；切片完成后应全绿，新增破坏单独报错 |
| `tests/knowledge/release/` | 固定 54 题、已发布方法案例/来源及整体验收的发布门；未补齐时明确失败并列出实际覆盖 |

完整发布门从早期就可运行，但不混进每次日常回归。它不能通过缩小分母、跳过或 `xfail` 把未完成改成通过。回归涵盖已交付能力的清单随交付更新，不允许为了通过而悄悄移除原有能力；当前切片的红灯修复后才算完成。

案例预期及错误样本与生产知识内容分开维护，不用生产输出自动生成答案。候选包试用不要求所有发布功能预先完成，但必须已有实际固定版本及内容审阅证据，不能用空实现演示。银行只用于判断通用路径不适用。新实现只跑相关测试及必要兼容回归；前端、事实库和导出无改动时记录其检查不适用。

## Risks / Trade-offs

- [把行业手册缺失当作通用知识已全面完成] → 固定 54 题分母，逐题说明通用路径与行业剩余范围；第七步仍有实际通用内容。
- [字段齐全但分析方法错误] → 规则级来源定位、独立撰写的案例预期、内容审阅与软件检查分开；单一自动评分不作发布依据。
- [同源转载造成虚假相互印证] → 记录原始出处与转载关系；来源数量不直接换算成可信度。
- [方法更新覆盖历史正文] → 追加不可变发布包，测试更新正文和映射后的旧版读取。
- [将内容待补状态传导成旧计算失效] → 独立知识入口及现有方法注册/报告读取的兼容测试。
- [只测少数问题却声称 54 题完成] → 自动枚举权威清单，按题检验通用路径，按所有已发布方法检查案例和来源，汇总显示未完成项。
- [长期存在的内容缺口遮蔽新的程序回归] → 日常回归与全量发布门独立执行并同时如实报告。
- [Agent 一律回答证据不足仍通过] → 充分证据和不足证据配对评测，分别检查支持关系与判断限制。
- [摘要丢失关键限制或输入名称相近导致误取数] → 默认结果保留关键边界并按版本展开，输入绑定检查定义及口径。
- [来源更正后仍沿用旧审阅] → 按内容身份验证审阅有效性，变更影响索引定位待复查对象。

## Migration Plan

1. 在新增命名空间加入知识模型、映射和只读入口，初始如实显示已有骨架待补，不修改旧内容成熟度。
2. 先以三个代表问题建立显式候选包，跑通 Agent 试用及旧版复现，再扩展内容和服务能力；候选包始终标明实际范围，不自动成为完整默认包。
3. 首版验收后才将完整 54 题发布包设为默认。停止新增入口或恢复上一仍有效的完整发布包即可回退；既有更正或撤回提示在回退后仍生效，不删除历史包。
4. 无 SQLite/DuckDB/Parquet 迁移，无 HTTP API 破坏性变更，无前端/导出改动。若实施发现需要这些变动，先更新规格与任务，不能扩展本变更的已确认范围。
