## Why

分析 Agent 已有八步研究问题清单，但现有方法库正文仍为待研究骨架，无法稳定提供有依据的分析步骤、证据要求和反例。需要先形成可验收的知识服务规格，再按 TDD 补齐测试、软件能力与方法内容。

## What Changes

### 已确认范围

- 使用者为分析 Agent；知识库返回方法、所需证据、反例和适用边界，公司数据计算、解释及最终判断由既有分析链路负责。
- 首版覆盖跨行业通用的八步方法，以[现有研究问题清单](../../../config/structured_data/research_requirements.v1.json)的 54 个问题为基线；具体行业手册后续建设。
- 由 Agent 检索公开可靠来源，记录原始依据及定位，整理方法知识。
- 按“确定需求 → 写测试并观察预期失败 → 实现并通过测试”推进。

### 本次需求草案

- 建立研究问题到可复用方法的映射；默认返回简短的操作指导，按固定版本展开详细方法和依据，重要限制及缺口不得被压缩隐藏。
- 统一方法内容合同，涵盖输入口径、步骤、证据支持关系、反例、缺失处理、来源与版本；定量输入绑定现有指标定义，原文证据说明查找内容与定位要求，未完成的数据映射明确留缺。
- 区分通用方法覆盖、行业补充状态、方法适用性和内容成熟度，避免占位文档被当成可用知识。
- 保留来源分歧、修订记录和历史方法版本；来源或规则变化时识别受影响的方法、问题及案例，新内容须重新审阅，旧内容仍可复核。
- 将日常行为/已完成内容回归与固定 54 题的完整发布验收分开；内容评测使用明确标准和刻意改错的案例检查，真实来源核验及人工内容抽查分别记账。
- 先对定价权、ROIC 口径及营运资本适用条件三个代表问题走通来源、测试、正文、读取、Agent 试用和版本复现，再扩展全部 54 题。候选样例包可以显式试用，完整首版条件不变。

以上行为细节及设计均为待审阅草案；本轮只交付规划文档，未编写测试、填充方法正文或实现软件。

### Non-goals

- 首版不建设白酒、银行等行业手册，不以通用方法宣称已覆盖行业专用模型。
- 不新增公司数据采集、数值计算、公司判断生成或投资报告生成能力。
- 不建设面向人的知识阅读前端，不要求向量数据库、知识图谱或开放式语义检索。
- 不改变既有报告、历史方法包、数据来源消费政策或其他变更的验收状态。

## Capabilities

### New Capabilities

- `eight-step-knowledge-base`: 54 个研究问题的通用方法覆盖、Agent 知识读取、内容与来源合同、适用性及缺口、分歧、版本和验收。

### Modified Capabilities

无。已有数据采集能力的行为合同不变。

## Impact

- 内容权威位置沿用 [docs/methodology](../../../docs/methodology/README.md) 和 [config/methods](../../../config/methods/method_specs.json)；规格描述知识服务行为及内容验收，后续金融方法正文继续维护在既有目录，本轮只交付规划文档。
- 预计在现有方法注册能力旁增加知识读取、覆盖、版本及变更影响检查和相关测试；问题和指标原始定义保持权威，不手工复制维护另一套编号、标题或财务口径。
- 对现有方法注册表采用兼容扩展。旧 `active` 和 `skeleton` 的语义保持不变；新知识服务有独立的内容可用性判断，不自动提升旧文档。
- 不迁移公司事实数据库，不改既有 API 响应、报告导出和前端。接口细节见 [design.md](design.md)。
- 本轮验证限于 OpenSpec 及规划一致性。后续完成须分别有软件测试、54 题通用内容覆盖、来源核验和人工内容抽查证据；结构校验通过不代表金融方法成立。
- 公开可访问不等于允许全文再分发；Git 只保存允许分发的整理内容及必要来源定位。方法依据记录版本、生效时间和取得时间，转载归并至原始来源，冲突与更正保留，不把后取得的知识当成历史时点已知。
- 项目总体目标和约束仍以[计划](../../../计划.md)、[来源规则](../../../docs/methodology/evidence_policy.md)及[版本规则](../../../docs/methodology/versioning.md)为准；本变更不把旧文档中的实施状态推断为当前运行状态。
