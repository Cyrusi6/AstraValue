## Goals / Non-Goals

**Goals:**

- 使来源成功、字段质量、数据可消费与历史/阅读覆盖成为可分别查询的状态。
- 一套字段/数据集注册驱动获取、计划、映射和检查，55 个数据集均有支持状态，不以少量核心指标替代范围。
- 数据集调度复用已交付采集存储与执行原语；新任务严格绑定自己的冻结上下文，旧运行按旧定义恢复。
- 程序保存全量字段，研究请求只读取相关规范事实和章节，不将全量响应或字段注册表反复送入 LLM。
- 从总方案八步问题向下登记数据需求，形成公司/问题/期间的可解释覆盖；新公司获取与行业专用支持分别判定。

**Non-Goals:**

- 不在本轮编写实现，不更改任何生产库、来源配置或计划任务。
- 不实现通用任意来源/任意 scope 插件平台；只交付此次结构化数据和重要阅读需要的明确入口。
- 不完成仍缺正式方法内容的治理画像方法；允许合格结构化证据准入，不自动生产治理评价。
- 不把上游返回字段的全部语义假装已经确认；缺定义字段保留原始命名空间和具体疑点。

## Decisions

### 1. 分开规划证据和可执行注册表

新增 `config/structured_data/`，存放以下独立版本对象，运行创建时同时冻结 canonical JSON 与 hash：

- `datasets.v1.json`：55 个数据集的 ID、真实上游、实际入口/SDK 方法、参数模板、允许参数、公司过滤、期间/日期字段、分页/目录方式、记录键、更新类别、适用性、保留和空结果合同。
- `fields.v1.json`：数据集原字段、性质、定义/单位状态、标准字段 ID、期间与 scope、换算、检查、主/备路由。完整登记本轮 2,487 个字段位置及动态未知字段，不能把位置数当独立指标数。
- `peer_sets.v1.json`：七家公司、目标/核心/经营比较角色、选择日期/依据及版本；代码同时保留交易所标准形式与供应商形式。
- `schedules.v1.json` 与 `reading_rules.v1.json`：调度日历、时区、重叠窗口、有限重试和 R01–R12。主源字段归属、阅读阈值与版本独立，避免改阈值使旧取数覆盖失效。
- `research_requirements.v1.json` 与 `industry_profiles.v1.json`：将下文八步输入附录转为可执行问题、必需/可选输入、取得路径、行业适用及覆盖规则；本轮只在设计中定义，后续实施才创建配置文件。来源数据版本与需求版本分离，新增问题不使有效原始响应失效。

注册器原子校验唯一 ID/version、hash、引用、日期、参数以及同一标准字段/期间/维度唯一主源。实际查询不是复制探针的两行 pageSize，也不能运行时任意拼接未知 URL。未取得接口证明的细项显式登记 gap；备选尚未实测时登记 `unvalidated`，触发时先完成其响应/同义映射检查，不能声称本轮已通过。

选择声明式数据集配合少数协议适配器，避免为 45 个东方财富表复制 45 套网络逻辑；不选择“动态执行网页脚本”或未经定义自动把所有数值列映射成财务指标。

### 2. 唯一字段主路由与部分成功

路由键为标准字段、期间类型、合并范围、业务维度及定义版本。先检查有效缓存，再合并同数据集请求；请求只由缺少有效输入的字段触发。

F01–F04 的原始金额采用东方财富；B02–B07 的已确认同义报告指标采用 BaoStock；F05 仅补充未被占用的扩展指标。当前股本取 G02，商誉余额取 F01、减值取 G12，同响应重复净利润/股数不另建默认真值。单季派生是明确期间的独立字段，不能用累计指标假冒。

取得一页后逐字段输出成功、空值、定义未知或校验失败。只有实际缺口进入有序 fallback，保留 `fallback_reason`、请求父项及被替代字段集合。备选同时返回的其他字段作为原始响应保留，不能覆盖主源成功字段或诱发新的双源对账。

备用计划限定为已定位的东方财富日行情、新浪三表和注册过的同义指标；中债是按需变量的独立主源，不是为了双源核验而访问。缺口无合法备选时保留，已有过期值明确显示取得时间与 stale 状态。

### 3. 接入协议与历史枚举

东方财富分四种协议处理：EM-S/EM-W 的分页数据集、EM-M 的不同分页参数、EM-F 的目录日期及对应报表、EM-Q 的当前快照。保留真实 reportName/columns/filter；公司类型先从来源页面取得并缓存，不能对金融业套普通企业类型。

- EM-F：先持久化资产/利润/现金流报告期目录，再为目录内日期创建报表分批任务；累计、单季分开。日期目录也是执行证据，不能在适配器内隐式发出不受计划约束的前置网络请求。
- 分页数据集：优先使用来源支持的稳定次级键；同期间多条记录必要时按期间分区后完整读取。去重键采用来源 ID 或登记的公司/期间/主体/业务维度组合，内容 hash 是版本键，不能单独充当业务主键。计数变化、重复页、无稳定键或无法证明终页时保留部分完成。
- BaoStock：匿名 SDK 接入，六类财务按年季、行情/复权按日期批次、证券基础与日历按其实际接口查询；全部耗尽结果集。历史起点取公司上市信息与供应商明确范围，不能从首个非空样本反推完整历史边界；不支持的早期范围留下明确可得性说明。
- SDK 的协议、成功码、查询范围和耗尽标记独立保存；`http_status` 保持无值，不伪写 HTTP 200。共享执行结果层需要显式支持 `http_response` 与 `sdk_result` 两种证明，旧 HTTP 证明规则不放宽为任意成功字符串。
- 当前快照（如市值、部分摘要）从首次取得开始积累历史，不用今日快照回填历史。

HTTP 默认直连、TLS 验证、受限端点和响应大小；来源限速以真实上游聚合，东方财富不同域名/数据集共享单并发和请求结束后三秒间隔。BaoStock SDK 同样受共享租约及来源门约束；巨潮保持原五秒策略。每次执行至多一次初次请求加一次有界补尝试，429/Retry-After 形成延后位置，达到上限保留失败，不无限循环。

### 4. 调度上下文复用共享执行记录

新增 `StructuredRunContext` 作为共享 acquisition run 的冻结附加上下文，包含 `acquisition_scope=structured_data`、field/question-set ID/version、query-pack ID/version、source-registry ID/version、各 hash、peer-set/schedule 版本及 ticker/namespace。物理任务和结果必须可反查同一上下文；本变更不把尚未实现的通用 scope 规划作为可用代码依赖。

采用专门的数据集 planner 与共享 run/attempt/lease/source-gate/snapshot 持久原语，新增必要的运行组合和 SDK 执行扩展。数据集 planner 输出明确目录/页面/报表日期/SDK 批次工作；不改写旧 business-model planner 的固定十主题。范围型数据集调度与旧公告 coverage 分开，旧 checkpoint 不能据同 ticker 直接成为新任务 parent。

`StructuredJob` 只保存调度身份、冻结上下文引用、公司/数据集/范围、父工作与共享 run 引用；尝试、租约、请求观测和原始内容继续使用共享记录。旧运行不要求新上下文；带 structured scope 的新运行必须存在上下文，缺失/跨公司/跨 namespace/跨版本关联在 I/O 或提交前拒绝。

恢复读取持久配置和已提交页，不能使用当前默认注册表替换。调度键包含政策语义、公司、数据集、时间分区和请求目的；执行尝试 ID 不进入业务去重键。任务与共享 run/上下文关联原子写入，成功页和记录投影使用幂等提交，租约过期不能写入完成状态。保留旧失败尝试，恢复用新尝试或明确 parent；不能清空失败日志模拟成功。

### 5. 存储与事实状态

在现有绑定数据库增加结构化模块的版本表、run 上下文、调度项、页面清单、记录/字段登记、覆盖与阅读任务附加表，使用模块迁移 ID `structured_data_0001` 和独立 schema 版本。复用公共 migration/backup/transaction 机制；不抢占尚未实施的全局 `0007_acquisition_scope_identity`，不静默提高全局 user_version 冒充该迁移完成。启动时精确验证模块表/索引/引用，模块迁移必须原子且幂等。

原始响应归共享 content blob/snapshot，模块记录以 row key + snapshot/hash 绑定版本；已知数值映射到现有 `FactRecord`，业务/事件行按类型化记录保留并提供字段路径，不能将所有表强塞成一个金额指标。未映射字段完整登记可查询，但不作为确定性公式输入。

新增结构化准入对象，将以下维度分别表达，并绑定实际 source、row/field locator、快照与注册表版本：

| 维度 | v1 值/约束 |
|---|---|
| 取得方式 | supplier_structured / document_extraction / formula / legacy |
| 数据性质 | observed / deterministic / provider_estimate / forecast / platform_label / source_text / unclassified |
| 质量 | passed / partial / failed / definition_unknown / not_applicable；partial 必须指出受影响字段 |
| 旧兼容显示状态 | 新增 `供应商直采`，旧七种保持；不得自动升级旧行 |
| 版本与定位 | source-policy/field-definition ID/version、snapshot hash、row key、field path、原值/单位、取得及业务日期 |
| 可消费性 | 程序依据实际来源、注册定义、性质、质量、时间与血缘计算，不采信调用者自填 true |

正常返回的客观记录及定义明确指标可以准入。公司简介、履历、调研回答留为来源文本；质押预警、项目预期回报、概念与预测进独立层。日期区分 report/disclosed/effective/retrieved/available；无当时版本证明时 available_at 采用取得时间，来源发布日期另外保存，严格历史不能提前使用。

累计转单季只在同年同范围输入完整时相减；TTM 只处理连续流量，不平均利润率或对资产负债存量滚动求和。空值不补零，负值不是通用错误。金额转元、股份转股、比率转小数；BaoStock 的季频不等于单季，分红每十股与实施状态、PCF 净现金流口径按字段附录处理。所有派生保留输入事实与公式版本。

### 6. 默认同步、报告和治理消费

`source_policy.json` 发布新 schema/版本并保留 `source_policy.v1.json`；旧 pair verification 行为通过明确 legacy 策略调用。`SyncRequest` 增加明确策略选择；未传 providers 的新请求采用 structured-first。显式旧 providers 且未传策略的历史请求保持 legacy 兼容并在响应回显策略，避免旧客户端静默进入新流程；新前端显式请求新策略。

新策略未显式限定 scopes/datasets 时计划该公司全部适用结构化数据集；显式子集只证明该子集覆盖。首批集合名固定指向七家；单公司路径以输入公司为边界，是否包括同行由集合参数表达，缺少目标不能隐式使用茅台。旧模型的默认 financials/market、五年和十二季度不能被误读为用户给新策略的限制。

全历史新同步创建持久任务后立即返回 202 和任务 ID，由独立执行入口处理，避免在一次网页请求中等待全部历史完成。200 的旧同步响应继续只用于明确 legacy 路径；新入口不能在任务仅入队时返回“同步成功”。已提交成功分区可形成带实际覆盖的逐公司 `SyncResult` 投影，供报告消费；其可用性不意味着整个任务或七家全历史完成。

`AdapterManager` 的新分支委托结构化调度/接入服务，不能在完成后再次走旧 consolidate 导致降级或双抓。`SyncResult` 保存实际策略、结构化覆盖、主备使用与缺口。新记录经过统一准入服务进入 `ReportStorage` 与 DuckDB/Parquet 投影；查询覆盖、全部记录和恢复读取不得保留 500 行截断。

`AnalysisService`、公式/市场倍数、reporting/API/exports/frontend 使用同一可消费规则。确定性 PE/PB 派生只在需要该独立公式字段且输入定义适用时计算；供应商 PE/PB 按指定主源直接供给，不为复算或复核重抓原值。报告显示直采可用、缺口与旧双源数量各自含义；不用“关键字段双源少”统一阻断新策略数据。

治理准入新增 `structured_supplier` 来源角色和响应行/字段证据定位，并复用类型、日期、身份命名空间和实际验证结果检查。修改角色不能放宽人员同名合并、任期、双时点或 LLM 候选边界；原正文证据仍按页/段落定位。

### 7. 更新调度和精读任务

调度按 [实施附录第 4/6 节](../../../docs/acquisition/structured-data-field-plan-v1.md) 执行：交易日 19:00 行情/估值，每日 20:30 目录/事件；摘要报告/事件触发及每周检查。交易日历缓存也记录真实覆盖；日历缺失不能猜作非交易日。财务由新报告期激活，供应商延迟记待更新，下次调度继续。

首次历史由近到远分批，完成水位只在分区终页和记录投影提交后推进。后续只取新期间/更新；事件无更新时间时最近 30 日重叠加未完成生命周期刷新，不能承诺发现没有更新信号的久远原地修订。行业/宏观、概念/预测仅对已激活研究类别调度，缓存供七家公司复用。

阅读队列保存材料 ID/内容版本、公司、报告期、规则 ID/version、输入事实、目标章节、原因、缺口与任务状态。R01–R12 的判断集中实现为纯规则函数；固定完整中文年报/中报与数值、事件触发合并。

- 数值按同期间同口径比较，百分点而不是百分数倍数；零/负同比基数、无正净资产分母、有息负债范围不明时记录输入缺口。
- 分红只比较两个已完成利润年度的实施合计；计划回购上限触发时明确它是上限。
- 初始基线不把所有旧任职/旧事件报成新增；仍有效事项、已有问题和固定报告可入队。
- 独立审计/英文年报先被正文策略排除；缺结构化值不触发全公告补抓。
- 同材料/内容版本多规则共用一份问题包；通过已有目录、ContentBlob、派生解析和主题章节定位复用；只有无可用内容时才创建具体正文工作。正文、解析和阅读沿用现有执行入口，在具体任务执行时调用；计划、去重和状态查询不调用 MinerU 或 LLM。

### 8. API、CLI 和可观察结果

新增 `/api/structured-data/` 路由：registry/fields、plans、runs、execute/resume、status/coverage、records 与 reading-tasks；具体命名在实现保持同一契约。创建计划/运行返回持久任务标识，执行由独立 worker/CLI 取得租约后推进，运行状态可查询；新同步入队使用 202。分页参数和 total/next-cursor 必须真实，状态接口不返回凭据、原始正文或不必要的本机路径。

CLI 增加 `structured plan|run|resume|status|records|reading-tasks`：plan 为零 I/O，run 接受公司/数据集集合与 baseline/incremental/due 模式，绑定显式 db/data-root；计划和运行均输出政策版本、实际范围与未完成项。`due` 一次执行到期工作后退出；未来需要持续运行时由显式 worker/系统调度调用，构造服务、测试和本轮规划不安装操作系统任务。

错误保持现有约定：无效配置/参数 422 或 CLI 参数错误，冻结版本/身份冲突 409，忙/租约占用 503，存储完整性错误 500；来源局部失败属于运行结果，不伪装整体成功，也不阻断已成功字段的读取。

### 9. 八步需求对象与独立覆盖快照

本变更需求基线为下文 54 个通用问题和 11 类行业画像；其目的是明确数据输入，不补写方法库正文或投资判断。问题 ID 使用独立 ES 命名空间，ES01.Q01–Q10 显式对应既有 BM.Q01–Q10 的相同主题，保存 crosswalk 和版本，不复制 BM 的旧来源覆盖或人工验收。

每个问题保存 step_id、question_id、标题、method_ref、适用谓词、期间模式、必需项、可选项及输出槽。每个输入项有稳定 requirement_id，拆到一个字段/有定义的记录集合/章节回答，不用数据集是否有行代表其全部字段。绑定包含取得方式、数据集与原字段或提取字段、单位/期间/范围、性质、主路由、替代组、检查、已有缺口和依赖。公式依赖组成有向无环图；循环、未知引用、空必需集合或跨定义替代在 loader 校验失败。

必需项组默认 all_of；只有经济含义、期间和范围相同的输入路径可组成 any_of，例如同一个产量字段由有效结构化记录或年报产量表取得。不能把“产量或营收”作为满足同一要求的替代。条件必需项使用 true/false/unknown：true 时参与覆盖，false 须有依据，unknown 保留待补。可选字段仍按既有全部适用字段策略获取，但不作为问题就绪分母；未选问题也不缩减已选公司的通用客观数据采集。

情景、驱动和结论中已有的假设/论点/模型运行作为独立 research_context 输入，绑定现有 AssumptionRecord/ClaimRecord/模型运行 ID 和其真实状态；没有这些对象时标 GAP11，不伪造外部取数路径。跨题引用只展开所需事实、章节或已有研究对象，不以“另一题必须可分析”作为递归依赖。例如 ES08.Q01 只读取前七步已生成的覆盖清单（允许有缺口），不能先要求七步全部完成；估值和情景共用基线与输入，不以彼此的覆盖状态循环等待。假设值存在且有来源可以使输入齐备，但其尚未确认仍阻止原有要求确认的模型执行。

新增 RequirementEvaluation 和 ResearchCoverageSnapshot 附加记录，复用本变更模块迁移和现有事实/解析引用，不创建第二套取数、同行或行业事实存储。冻结公司及证券身份、需求/字段/行业/同行/方法版本、研究时间范围、输入版本、生成时间。来源未公布的目录未知期单独显示，不能猜具体报告缺失。需求调整可复用有效快照重新计算覆盖；旧覆盖快照不覆盖，旧报告缺少该对象时显示“该版本未评估”，不能回填 100%。

### 10. 数据就绪与研究完成的判定

数据项原因包括 ready、source_empty、source_failed、not_disclosed、unmapped、definition_unknown、reading_pending、stale、formula_input_missing、unsupported、applicability_unknown。来源无记录仅为 source_empty；not_disclosed 需要对应披露范围的材料依据。查不到接口不能变成公司业务不适用。显式零值仍须证明单位和期间，不能由空值替代。

问题的三个用户状态按以下顺序计算：

1. 不适用：问题谓词明确为 false，保存规则/证据与有效期间；条目继续显示。
2. 待补：适用性未知，或任一适用必需项在要求期间不为 ready；列明缺什么、影响哪个输出、已有证据和下一条已登记取得路径。无可行路径时注明当前免费来源未覆盖，不反复重试。
3. 可分析：适用为 true，存在非空必需集合且全部满足；含义固定为“本问题输入齐备”。method_status、assumption_status、analysis_status 分别显示为方法待完善/可用、假设不需要/待确认/已确认、研究未开始/进行中/已完成。数据就绪不改变其余三者。

步骤仍以同样三状态聚合：全部问题不适用才为不适用；存在适用性未知或待补问题时为待补，并列出已可分析的问题；全部适用问题可分析才为可分析。整体数据就绪统计为 ready_question_count / applicable_or_unknown_question_count；不适用数和可选项另列，分母为零时显示无适用项而非 100%。不按原字段数、已下载 PDF 数、分页成功率或旧 evidence_scores 替代。始终展示八步，未选步骤写未评估并作为待补原因，不静默删除。

按问题/公司/期间保存明细并支持分页，聚合必须遍历全部明细；同一输入共享给多题仍只有一份取数任务，每题保留自己的需求是否满足。API/CLI/报告/导出使用同一覆盖快照 ID，旧证据完整度保留原标签，不能改名成八步完整度。新接口增加 company-resolution、industry-profile、peer-candidates 和 research-coverage 资源；CLI 增加对应 resolve/profile/peers/coverage 子命令。纯查询零 I/O，缺主数据的 plan 只列身份前置任务，显式 run 才执行。

### 11. 新公司、行业与同行范围

身份解析优先本地有效主数据：证券身份主用 B08 的 code/code_name/type/status/ipoDate/outDate，法律主体、曾用名、市场及行业主用 C01 的 ORG_CODE/ORG_NAME/FORMERNAME/SECUCODE/SECURITY_CODE/TRADE_MARKET_CODE 等字段。C01 为 B08 未覆盖证券身份的备选，只有实际缺口才请求；同一 C01 响应中的额外字段完整复用。名称查询或候选枚举参数须独立登记并验证，不能把单公司探针参数假称支持任意模糊搜索。

带交易所代码必须与实际市场匹配；仅名称唯一匹配且证券类型为目标 A 股才可自动继续。重名、曾用名跨期、代码市场冲突均返回候选；港股/B 股/基金等不自动替代 A 股。沪深及北交所分别显示适配能力：BaoStock 未覆盖的市场走已登记兼容备选，没有支持时留市场缺口，不因六位代码可解析而承诺支持。公司主体 ID 与证券 ID 分开，多证券共用公司财务，同日行情/币种/股本类别分别绑定。退市不等于公司不存在，停牌不等于财务不适用。

行业画像由 C01 的 CSRC_INDUSTRY_NAME、SWINDUSTRY_CODE2/SWINDUSTRY_NAME2 及版本/取得时间，结合 C02 的主营分类/金额和来源报表 companyType 形成。平台概念仅供发现方向。分类属于来源标签，研究画像属于版本化规则选择；不能把类别名称转换成竞争优势。未知行业只启用已证明适用的通用项，保留行业待确认；新策略不沿用 IndustryRouter 的静默 general 回退，legacy 保留原行为。

多个行业业务并存时启用多个画像，保存相关分部和比例；连续两个可比年度同一主营分类占比均至少 50% 才可用于单一主业的自动选择，缺期间、分类冲突或低于阈值时保留混合/待确认。该 50% 是本版研究调度规则，不是会计重大性标准；已明确的银行/保险监管类型仍按其报表协议和专用输入，不用收入阈值把它们改成普通企业。尚未盈利是叠加画像，不删除所属行业需求。

同行流程：优先适用的已选 PeerSetVersion（首批名单原样保留）；新对象用同一供应商分类体系发现候选，再取得必要主营/基础证据筛查。身份/分类成员列表为轻量前置任务，可分页；该筛查只取 C01/C02 及必要比较字段，不自动下载所有候选历史财报。分类成员查询未获协议证明时明确 candidate_discovery_gap，可使用已有候选/用户给定名单，不能凭空列出同行。

自动纳入须同时具备共同主营映射、主营占比条件、可解释的模式/地域匹配和同一比较期间；行业字典只做版本化可重放的名称映射，原分类不变。文字无法确定的模式/地域留为候选待评估，不用概念标签、同名产品或模型自评强行通过。规模按同期间营收比例接近程度排序，再按证券 ID 排序打破平局，默认最多六家；不足不凑数，未入选候选及理由保留。经营比较保留亏损同行，PE/金融专用估值按其方法适用子集筛选。每项选择保存来源、依据、规则版本、decision_kind=rule_selected 或 user_selected；只有真实用户确认才写 user_confirmed，规则结果不冒充人工。

显式 company-only 请求保持目标公司边界；company-with-peers 请求执行上述有界发现并仅给入选公司安排全历史。不递归抓同行的同行。缺同行只影响同行比较问题，不阻断目标独立财务；既有七家集合不扩展为其他公司的默认同行。金融、其他行业接口与关键字段必须在后续隔离样本按具体公司类型验收，通过一类不表示其余行业通过。

### 12. 需求驱动阅读与补充边界

下文 RD 章节是新增八步输入的定位词典，沿用当前正文获取、MinerU 和带出处事实表，不复制旧 BM 主题/答案数据库。R01–R12 仍为阅读触发规则；RD01–RD12 只表示章节路由，二者不混用。必需项依赖正文时检查已有事实/答案，再检查已有解析，生成精确到公司、报告期、提取字段及章节的待答问题。已完整取得的年报/中报按既有固定队列复用，其他材料仍须具体问题/R 规则；招股材料仅已有可用档案或明确起源/发行问题需要时使用。

章节回答保存原文或表格、字段值/单位/期间、文档和解析版本、页码/HTML 段落、质量与问题 ID。机器解析完成、关键词命中、仅有目录标题和宽泛摘要都不能满足必需项；沿用现有证据准入与复核状态，不增加全体供应商字段的人工作业。缺口没有找到时保留检索范围及“本材料未检出”，不能改成公司无此业务；明确无事项的披露可形成负向事实，只对其覆盖期间成立。

八步需求补充阶段只更新了现有七份 OpenSpec Markdown，字段名由已有结构 JSON 本地核对。其后按用户要求补充本地官方技术文档快照及实施参考入口，没有执行新的业务数据接口探针。上位实施计划旧段落“OpenSpec 尚未创建”属于此前阶段状态，本轮合同已经存在；后续文档交接任务须同步该状态，不能用旧段落否定本合同，也不改写历史日志。

## Risks / Trade-offs

- 公开接口字段与分页可能变化 → 注册表版本、全部原字段登记、稳定键/总数/终页校验及明确部分完成；不承诺 API 文档之外的稳定性。
- 同一来源多域名与 SDK 跨进程并发 → 以真实上游共享门和租约保护，测试真实并发/过期写拒绝；不另造每数据集独立限速岛。
- 旧消费链隐含双源前提 → 新策略显式分支，统一准入谓词，旧状态/旧算法保留，覆盖报告、导出和治理读取路径。
- 全历史工作量大 → 可恢复分批、状态可见、限速有界；软件验收与七家全历史生产验收分开。
- 单体报表、关联交易、完整任期、债券生命周期与白酒量价仍有缺口 → 注册具体缺项，采用已允许补源或正常重要报告精读，不虚构字段或扩大 PDF 范围。
- 新数据集层与未来通用 scope 迁移有交集 → 附加上下文明确冻结五维身份；不重写旧可信根，将来迁移需显式兼容映射，不把两种覆盖互认。
- 需求登记完整但免费来源不能满足全部输入 → 明确必需项缺口及受影响问题，不承诺任意公司八步信息齐全；行业样本与输入覆盖独立验收。
- 八步数据就绪与方法/假设混淆 → 同屏分列三状态数据覆盖、方法及研究状态，不自动代签假设或把骨架方法发布为已完成。

## Migration Plan

1. 先实现并验证注册器、映射/准入、调度上下文与共享执行扩展；新代码测试只用临时绑定库和合成数据。
2. 增加模块迁移前先创建并核实数据库备份；在一个事务中建表/索引、记录模块版本、验证引用和旧行保持。空库、已有 v6、重复迁移、错误 schema、并发与中途失败均需测试；不改变旧运行/manifest payload/hash。
3. 新默认策略通过显式新同步入口生效；旧 API 请求兼容规则和旧策略文件一同交付。旧事实不批量重新标记，要用于新策略时从已有有效快照产生带新准入依据的新版本。
4. 在独立临时 namespace 完成代表性真实样本与增量/恢复验证，原始响应、数据库和报告留在 Git 忽略目录。生产全历史尚未执行时明确保持 pending。
5. 用户后续要求生产执行时，绑定实际路径和冻结配置，再按七家集合分批运行；生产状态以已完成分区与覆盖报告为准。
6. 回滚停止新任务创建/执行并切回明确 legacy 策略；保留新增表与证据供新版本读取，不运行破坏性 down migration。完整数据库恢复仅在相应部署恢复授权下使用已验证备份。

## Validation Strategy

- 离线：主源成功零备选、部分字段失败、分页 500+、重复页/总数变化、合法空结果/错误页、范围/版本混用、租约失效、恢复和幂等；55 数据集契约分组夹具和完整登记覆盖。
- 消费：仅供应商关键财务可用，未知定义/观点/估计不进入实际值；年度/累计/单季/TTM、单位、实施状态和 available_at；报告、导出、治理准入及旧记录保持。
- 调度/精读：北京时间和交易日、供应商延迟、30 日重叠/未完成事项、固定年报/中报、R01–R12 各分支、输入缺口、同材料合并、停采和已解析零请求复用。
- 项目：聚焦 pytest 后全量、方法库/来源/治理注册和黄金清单结构、SQLite/DuckDB/Parquet 一致性、前端 build、严格 OpenSpec 与 diff 检查。既有人工 pending 不由自动测试改写。
- 真实样本：执行阶段以隔离库验证东方财富分页/三表、BaoStock 行情/财务/SDK 空结果及有界恢复，记录确切公司/数据集/范围；备选只在实际/受控缺口触发时验证，不做成功主源双源对账。
- 本轮规划：只验证文档合同完整性、引用、结构与 strict OpenSpec；不将任何待执行项目勾选为完成。
- 需求：54 题每题至少一个明确必需项、可选项与期间/适用规则，原字段引用均能解析，11 类画像均有具体专用输入和支持状态；空响应、不适用、未知行业、同名公司、多证券、混合主业和未盈利边界均有后续测试。
- 覆盖输出：合成公司展示八步和部分就绪；验证方法 skeleton、历史缺季、显式无事项、可选缺失、旧覆盖重放、新版本增加必需项、500+ 明细与报告/API/导出一致性。示例只能称合成数据，不能当任何真实公司验收。

## Eight-step Demand Contract

以下为待实现的数据输入基线 research-requirements.v1，依据 [总方案八步目标](../../../计划.md#2-八步框架的补充内容)。54 题将目标拆到可以检查的数据要求，11 类画像再添加条件输入。登记完成只证明每项需求都有取得路径或明确缺口；不证明全部免费数据已存在，也不替代 [八步方法文档](../../../docs/methodology/README.md) 的研究方法与确认规则。

### A. 引用、期间与必需项解释

- F/C/G/A/B/M/I/L/P/T 编号均引用 [接口字段附录](../../../docs/acquisition/structured-data-field-plan-v1.md)；如 F01.MONETARYFUNDS 表示该数据集的精确原字段，实际端点和参数由原附录及可执行注册表定位。F04 同时含单季利润和现金流两个独立数据集，实施映射必须拆分，不能只用 F04 作为唯一物理数据集 ID。A03 同理拆增发和配股；B08 拆基础、日历和复权。
- 下表“必需”是回答该题所需的事实或证据，不代表一律用接口数值回答。并列项默认全部必需；标有“若存在/若采用”的输入按可证明条件激活，条件未知仍待补。可选项缺失不阻断该题；既有全字段获取策略保持。
- NOW：截至 as_of 的最新有效记录，附真实有效期和取得时间。FIN：默认最近五个完整年度和十二个已公布季度，季度存量取季末、流量按累计/单季定义分别取；同比和 TTM 另加载必要前期依赖。BIZ：最近五份年报及最新中报的相应经营期，同期比较另取上年同一中期。EVT：最近五年及更早尚未终结事项，状态变化全链保留。IND：与目标比较期间一致的年度五期，价格/库存等月度序列默认近六十个已发布月份；数据频率不同须显式重新定范围，不能插值伪造观测。SCN：最新已知基线及用户选定的预测期间。
- 分析窗口与全历史入库分开；显式请求更短窗口只缩该次研究。上市前不属于该次公开报告义务的期间可按身份规则排除，但可得招股/供应商历史仍采集；上市后缺历史、早期公司改名和供应商覆盖较晚都不能伪装不存在。IPO 年份或业务变化使部分条件适用时按期间计算，不把当期不适用扩展到全历史。
- 表中“无已验免费接口”表示本轮缺少对应有效接口证明；可先复用正常精读所得的具体字段。找到新来源须登记、确认长期免费及单位/期间后再纳入，不能在本轮凭来源名称填成已覆盖。

### B. 重要报告章节与提取目标

章节标题为定位词典，不是固定页码或每家公司必然披露。所有提取字段同时保存公司、期间、单位/定义及 RD 路由，页码/HTML 段落在实际材料取得后绑定。招股、专项或事件正文仅在具体问题需要且符合既有重要性策略时读取；独立审计 PDF、英文年报继续停采。

| 路由 | 优先材料及章节 | 需要提取的字段/证据 |
|---|---|---|
| RD01 | 中文年报/中报：公司业务概要、经营模式；已有招股书公司沿革 | 主体沿革、产品/服务、定价/结算方式、收入确认与收现模式；披露描述和分析判断分开 |
| RD02 | 管理层讨论：收入成本、分产品/地区/渠道、主要客户供应商 | 类别、收入、成本、利润口径、单位、采购/销售分母、匿名/集中度及渠道变化 |
| RD03 | 经营情况：产销存、产能、在建工程、主要项目 | 产品产量/销量/库存、设计与有效产能、利用率定义、项目进度及投产时间；计划与实际分开 |
| RD04 | 研发投入、员工情况、核心技术与研发项目 | 费用化/资本化、研发人员、项目阶段、专利/新产品证据、员工及平均口径 |
| RD05 | 财务附注：报表基础、合并范围、应收、存货、税项、非经常损益、收入确认 | 范围变化、账龄/减值、关联科目、有效税率说明、政策/估计变化；需要单体时取明确母公司报表 |
| RD06 | 财务附注：受限资产、借款、债券、租赁、现金流补充资料 | 可动用现金、有息债务组成与到期、利率/担保、折旧摊销、不涉现金事项与营运资本范围 |
| RD07 | 公司治理、股东及关联交易、承诺履行、重要事项 | 人员任离职和身份、实控链、关联方与交易金额/条款、承诺对象/期限/履行状态 |

| RD10 | 经营讨论：战略、未来发展与风险因素；触发事件正文 | 具体驱动、约束、变更日期、预期目标/时限、风险暴露、反证和跟踪变量 |
| RD11 | 股权激励/员工持股重要公告、股份支付附注 | 授予/行权/解锁条件、目标、人数/股份、摊销、失效/完成及潜在稀释 |
| RD12 | 完整中文年报内审计意见、内控评价、监管事项与整改 | 审计/内控意见、缺陷、整改目标/进展、机构更换与范围；不请求独立审计 PDF |

### C. 程序计算的输入路径

以下只定义数据转换和依赖。既有方法未就绪时保留输入，不在采集层补造投资方法。单位、期间、合并/归母范围、来源定义不满足时记录 formula_input_missing 或 definition_unknown；确定性运算与带未来假设的模型计算分层。

| 计算路由 | 输入与计算/输出边界 |
|---|---|
| K01 | F02/F03 同年同范围累计相减得到单季，F04 有明确定义的单季优先；连续四个单季流量组成 TTM。同比需同口径同期且正基数，零/负基数单列绝对变化和盈亏切换，不输出误导百分比 |
| K02 | C02 分项收入/相同分类总收入得到构成占比；F02.OPERATE_INCOME 与 OPERATE_COST 得毛利率，SALE_EXPENSE/MANAGE_EXPENSE/RESEARCH_EXPENSE 得相同营收口径费用率；金融收入成本另走行业定义，父子分类不重复加总 |
| K03 | 优先 B07 已定义杜邦字段、B02.roeAvg 及 F05.ROIC；需要另一个 ROE/ROIC 口径时，明确净利润/归母、期初期末平均资产/权益、NOPAT/投入资本定义与方法版本，不能混用平均与加权指标；WACC 是独立带参数方法输入，不自动用有效税率替代经营适用税率 |
| K04 | F03.NETCASH_OPERATE / 同范围 F02.NETPROFIT 得现金利润比；净利润减经营现金流及平均资产得到登记口径的应计指标；B03 周转率/天数直接用。分母非正或平均期缺失需解释/留缺，不能把非适用的比率当零 |
| K05 | 有息债务须由 F01.SHORT_LOAN/LONG_LOAN/BOND_PAYABLE/LEASE_LIAB 等已确认组成，加 RD06 拆出一年内到期与其他有息部分；净债务再扣同口径可动用现金。字段集合未证明完整则只能保存分项，不输出完整有息债务/净债务 |
| K06 | F03.CONSTRUCT_LONG_ASSET 为购建长期资产支付现金；经营现金流减该项可得明确命名的现金流代理，不能直接改称 FCFF。FCFF 需要 NOPAT、折旧摊销、资本开支、营运资本变动及方法定义；F03.FA_IR_DEPR/IA_AMORTIZE 等只按互斥定义取用，维护/扩张开支缺分解时留缺 |
| K07 | A01 已实施分红按利润年度合计：PRETAX_BONUS_RMB 每十股换每股，结合实际分配基数得到现金额，再与同年度归母利润/对应价格比较；分配基数不明确时不以当前总股数替代。回购只以实际金额/实际股数形成执行比例，计划上限独立 |
| K08 | F02.BASIC_EPS/DILUTED_EPS 为披露口径；G02 股数和 RD11 潜在股份构成稀释输入。预测 EPS 必须用归母利润、适用加权股数及潜在稀释假设；不能把期末股数反标为已披露基本 EPS 分母 |
| K09 | B01 的 PE/PB/PS/PCF 直接用；估值历史分位按冻结窗口和有效交易日经验分布计算，平值取中秩并保存样本数/缺失日。同行比较固定同期间/定义/角色子集，不为数量凑齐而混用亏损 PE；EV/EBITDA 需要同日总权益市值、完整净债务、少数股东等方法组成及定义明确 EBITDA |
| K10 | 产品单位收入/成本仅用同产品/范围销量及收入/成本；产能利用率仅用明确定义的产量和有效产能。公司份额/CR3/CR5 要同产品/地区/期间的行业分母及完整对应分子，少数同行和社零不能代替；依据覆盖不足的计算进入独立估计层 |
| K11 | 情景模型引用既有 method_ref、实际基线和已确认的销量/价格/利润率/税率/资本开支/营运资本/折现及终值等 AssumptionRecord，输出盈利、EPS、FCF 与估值区间。未确认假设不填历史实际字段，不自动赋情景概率或替用户确认 |

| preprofit 尚未盈利（叠加） | F01.MONETARYFUNDS 与 RD06 可动用现金/到期债务，F03.NETCASH_OPERATE/CONSTRUCT_LONG_ASSET，G02 股数；RD01/RD10 商业化里程碑、融资状态；剩余现金月数需显式未来消耗假设 | 融资条款、用户/订单队列 | 保留原行业要求；ES02.Q04/Q07 负分母按定义处理，ES05 不强行 PE/常规 DCF；ES08 现金跑道属于假设计算，不是确定未来事实。是否可持续盈利需要研究，不能用本期正利润自动关掉画像 |

行业材料仅给定章节方向时，取得路径状态为 reading_required；没有可用章节回答仍是待补。API 有列名但定义/值未验为 candidate_mapping，不得算作已支持；没有免费路径为 unsupported_free_source。这三类在清单分别显示，避免所有缺口都被误标为联网故障。

### F. 已知缺口的处理合同

每个缺口实例保存 gap_id、requirement_id、公司/行业/期间、已检查来源、最近结果、可行下一步和重试资格。gap 不是伪值，不会被 55 个数据集的其他成功字段抵消。可用章节不存在时保留当前不可得，不能因此删掉必需项或用接口总数充抵。

| 缺口 | 受影响输入 | 下一条允许路径与完成证据 |
|---|---|---|
| GAP01 单体与合并细项 | 母公司三表、合并变动、政策/估计变化 | 复用重要报告 RD05；独立明确表头/期间/单位和字段记录满足相应项，默认三表不能冒充单体 |
| GAP02 客户供应商及量价 | 匿名/空客户表、渠道、产品销量/产能/单位成本 | C03 同义备选有证明才用，否则 RD02/RD03；匿名数据只能满足集中度等匿名可答问题，不能满足对手方身份 |
| GAP03 治理条款与任期 | 完整离任、关联交易、承诺、激励条件 | RD07/RD11；保留主体、有效日期/条款/履行状态，关联担保不替代全部关联交易 |
| GAP04 并购与债券生命周期 | 并购对价、承诺履行、债券当前余额/转股/赎回 | RD08/RD06 的对应交易/债券及状态；发行记录或初始转股价不能关闭当前生命周期缺口 |
| GAP05 财务附注与模型组成 | 有息债务、可动用现金、表外事项、维护开支、投入资本、EV/EBITDA | RD05/RD06 逐项补字段，K05/K06/K09 验证组成完整；不能把部分合计升级成全额 |
| GAP06 行业规模与集中度 | 同产品/地区/期间的行业分母和 CR3/CR5 分子 | 已登记长期免费统计资料或 RD09 中可追溯同口径资料；仍无可靠来源则当前不可得，不用同行样本替代 |
| GAP07 行业量价与供需 | 白酒批价/渠道库存及其他行业运营变量 | RD03/RD09 的实际披露，新增免费源需单独注册/验证；文档没有终端数据时明确不可得，不承诺仅靠年报补齐 |
| GAP08 金融行业字段 | 银行/保险/券商 F05 候选及报表 companyType | 实施阶段隔离验证相应真实公司和期间，或 RD05/RD09 明确值/定义；普通企业空列样本不能关闭缺口 |
| GAP09 利率与行业免费备选 | 中债国债曲线等仅定位未实测入口 | 首次相关任务验证已定位免费协议/窗口/单位；不把本轮探针记作成功，估值采用该输入前必须已有有效记录 |
| GAP10 新公司身份与同行 | 模糊名称、市场支持、分类成员、业务可比性 | 已登记主数据前置任务和有界候选筛查；唯一身份/证据缺失时精确说明，目标其他已可用输入继续保留 |
| GAP11 方法与假设 | 方法 skeleton、未来参数、评级确认 | 单独记录 method/assumption/analysis 状态；由后续方法工作和真实用户确认闭合，不触发数据重抓，不作为供应商失败 |
| GAP12 上游历史/定义边界 | 报告期断档、未知单位、长期免费不可得字段 | 现有同义免费补源、已存在重要报告或新注册来源；仍缺时保留具体期间/字段。完整登记和供应商可得范围完成不等于研究需求齐备 |

### G. 输入公司后的覆盖输出与验收

一次研究请求必须绑定目标身份和 as_of，默认八步全部启用，可显式覆盖分析窗口。公司识别、行业画像、同行候选/入选、采集分区、逐题数据就绪各有独立状态。字段使用标准单位与事实/章节定位，用户界面不要求理解原始供应商字段名；展开详情可以看到必需项、已得项、缺口与下一条取得路径。

以下为接口/界面合同示意，没有执行任何真实公司查询，不是茅台或其他公司的当前结果：

| 输出层 | 必须显示的内容 |
|---|---|
| 公司 | 规范证券代码、法律主体、现名/曾用名、市场、身份解析结果；歧义时显示候选 |
| 行业 | 分类来源/版本、研究画像及其依据、混合/未确认状态、专用适配能力 |
| 同行 | 目标、入选与未入选名单/理由、规则或用户选择、比较期间和逐指标可比子集 |
| 八步概览 | 固定八步顺序，每步可分析/待补/不适用、各状态问题数、数据窗口、方法和研究状态 |
| 每个问题 | question_id、必需项/可选项、有效证据、条件/期间、缺项/缺因、影响的输出、补充路径 |
| 获取进度 | 数据集/分区的成功、空记录、失败、待执行与可得历史边界；独立于研究问题覆盖 |
| 版本 | 来源/字段/需求/行业/同行/方法版本、as_of、覆盖快照 ID 和计算时间；导出引用相同版本 |

后续至少验证以下端到端合成案例，并单列真实样本支持范围：

1. 有最新营收但缺历史同期：最新截面输入可用，ES02.Q02 的趋势部分待补；已有数据可展示。
2. 已解析年报但无产量回答：ES01.Q04/Q05 仍待补，只安排 RD03 的问题提取，额外下载/解析为零。
3. 供应商空质押表：ES03.Q02 待补；明确年报说明覆盖期间无质押后，存在性输入就绪，质押条款子项可不适用。
4. 新银行：公司可识别、普通收入字段有效，净息差/资本字段只有名称；银行专项问题待补，通用 FCFF 不适用，没有 general 兜底估值。
5. 所有必需输入齐备而可选预测缺失：数据状态可分析；方法 skeleton 或情景假设未确认照常显示待完善/待确认，不自动生成最终评级。
6. 同行不足、亏损或模式未知：目标独立问题正常计算；可比子集/候选缺口只影响对应同行问题，不把同行的同行加入采集。
7. 更换需求版本或行业画像：新覆盖重新计算适用性与输入，旧覆盖/报告保持；同源已得响应、正文和解析复用。
8. 超过 500 条需求明细且最后一项缺失：问题、步骤、API/CLI/导出均包含该缺口与真实计数，不出现接口全成功而八步全绿的误报。
