## Why

当前财务同步默认依次访问正式披露、AKShare、新浪和 BaoStock，关键字段缺少正式披露时仍被降为待核验；公告执行器围绕商业模式正文覆盖，不能表达已经选定的“结构化字段主源成功即可消费、只有缺口补源、重要报告按问题精读”。本变更落实 [字段与阅读基线](../../../docs/acquisition/structured-data-field-plan-v1.md)、[数据层计划 v2.1](../../../八步全量研究数据层实施计划.md) 和 [来源规则](../../../docs/methodology/evidence_policy.md)。

## Delivery Boundary

用户已明确本轮仅形成完整变更合同，后续另行要求实现。当前交付限于 proposal、specs、design 和 tasks；下文为待实现的目标行为，源码、运行配置、数据迁移、联网执行和调度部署均不在本轮执行。

## What Changes

- **BREAKING（新同步默认行为）**：新研究同步采用版本化结构化来源策略，东方财富供给公司结构化数据，BaoStock 供给日行情、估值及已登记财务指标；停止默认多源财务抓取和 PDF 逐字段核对。显式旧调用和旧快照保留原语义，不倒改历史。
- 建立可执行的数据集与字段注册表，覆盖已实测 55 个数据集及全部返回字段登记；每个标准字段/期间/维度指定一个主源，备选仅在实际缺失或失败时调用。未知字段登记保留，标签、文本、预测和估计分层。
- 增加供应商直采的来源、数据性质、质量和可消费状态，贯穿入库、整理、报告输入、API、导出与前端展示；不将其伪装成双源一致或权威单源。
- 为七家公司建立分批全历史、按报告/日行情/事件/按需类别更新的持久调度；冻结策略与参数，分页走完，失败保留，可恢复、可去重。复用现有数据库、内容存储、来源限速与执行证据能力，不复制生产控制面。
- 将目录与正文任务分离，落地完整中文年报/中报和 R01–R12 阅读条件、同材料任务合并与已有内容复用。独立审计 PDF、英文年报保持停采。
- 增加八步问题的数据需求合同：逐题列出必需/可选输入、行业和事件适用条件、接口原字段/计算/精读路径及已知缺口。按公司、期间和问题输出“可分析 / 待补 / 不适用”，资料齐备、方法就绪与结论完成分别显示；不能用 55 个接口成功率代替研究覆盖。
- 增加新公司身份解析、行业画像和同行选择规则：首批七家公司保留为已选集合；其他 A 股公司按唯一证券身份进入通用获取，行业字段能力和同行业务可比性独立判定，未知行业不静默套普通工商估值。

### Non-goals

- 补齐的是八步研究的数据输入合同，不编写或验收完整研究方法，不改变评级确认、估值假设或治理报告自主发布的独立决策；方法 skeleton 不升级为已验收方法，数据齐备不自动形成结论。
- 不默认扩展到全市场，不接入限时试用或付费必需源，不实施交易、攻击或访问控制绕过。
- 不将当前供应商历史序列当作严格 PIT 回测数据；不主动追查全部正式更正，不下载全部公告补接口缺口。
- 本变更交付软件与隔离联网样本；不自动启动七家全历史生产归档、修改当前生产库或代签人工黄金验收。全历史运行由交付命令显式启动，并如实报告未完成批次。

## Capabilities

### New Capabilities

- `structured-source-routing`：数据集、字段和主备源合同，全部字段登记、八步需求映射与行业字段能力。
- `structured-fact-consumption`：供应商事实准入、性质分层、时间/单位与历史兼容，逐问题/逐步覆盖与报告/API/导出消费。
- `structured-acquisition-scheduling`：首批七家及新研究对象的身份/行业/同行范围、全历史与增量任务、缓存、限速和恢复。
- `important-report-reading`：轻量目录、固定和问题驱动的阅读队列、章节证据与未回答状态、停采及材料复用。

### Modified Capabilities

无已发布主 spec 可直接修改；现有 `openspec/specs/` 未发布上述能力。原业务采集、目录恢复和治理变更保留历史，新增行为由本变更契约与来源策略版本标识。

## Impact

- 配置：`config/methods/source_policy.json` 新版本及旧策略保留；新增结构化字段/数据集、同行、调度与阅读规则配置。规划字段 JSON 是输入证据，不能直接当生产配置加载。
- 后端：`analysis.models/policies/verification/adapters/manager`、共享 storage/snapshot/source gate、报告与消费选择器；新增 `analysis.structured` 接入与调度模块。核实 main 尚无已交付的通用五维 scope 迁移，不依赖历史规划文件冒充可用实现。
- 存储：新增调度、页面/记录覆盖和阅读任务等附加表；旧事实、同步、报告及源快照保持不变。缓存与调度身份必须包含公司、数据集、策略版本、期间和业务维度；旧商业模式 checkpoint 不能证明新结构化数据完整。
- 入口：提供计划、执行、恢复、状态及字段/记录查询的 CLI/API；现有同步入口接入新默认路由，显式旧模式可复现历史行为；前端与导出真实显示新状态。
- 边界：上游只有一次有效响应就可用，但免费字段范围、分页/空结果、供应商原地修订和获取时间仍需记录；不同封装不算独立上游。同义备用不得替换不同期间、合并范围或定义；缺数据不造值。
- 验收：分别执行离线行为测试、SQLite/DuckDB/Parquet 一致性、方法库/前端检查、隔离真实接口样本与人工验收状态记录；不把字段探针或绿色测试当作全历史生产完成。
- 需求覆盖：以 [设计中的八步输入与行业附录](./design.md#eight-step-demand-contract) 为本软件变更的冻结需求基线，关联 [总方案八步目标](../../../计划.md) 和仍未完成的 [方法文档](../../../docs/methodology/README.md)。扩展问题/行业版本需重新计算覆盖，保留旧结果；没有免费来源的必需项继续显示待补。
