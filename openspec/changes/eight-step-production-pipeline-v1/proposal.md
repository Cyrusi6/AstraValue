## Why

数据采集、标准化和轻量包已在选定白酒样本上形成真实成果，但现有报告由代码拼接观察与固定句式，不能完成用户需要的公司研究。现按[四层产品职责](../../../计划.md)纠正端到端分工：框架准备资料，Codex／Claude Code 自主研究和写作，代码负责计算、绘图与组装。

## What Changes

- 保留已验证的采集、后补字段解释、标准化、期间整理、原件定位、范围控制和紧凑输入；完善高层任务准备／补采／恢复／状态，使模型不再处理来源查找与文件拼接。
- 增加按问题有界检索的知识合同，参考资料包含出处、适用条件和反例；按需建设，现有 skeleton 不升格为成熟知识。
- **BREAKING**：新自主研究流程取消预测假设和评级的逐项用户确认前置门；模型负责提出假设、调用估值计算、给出敏感性、明确结论和评级。旧报告与确认记录继续可读。
- 接入真实模型研究成果；代码不得用原文摘录、固定结论句式或非空 ClaimRecord 代替研究。数值和图表统一引用冻结事实与计算结果。
- 最终正文以结论、解释及趋势／比较图为主体，详细表格、内部编号和完整来源记录放入附录。先验收贵州茅台，再验证其余六家白酒；前端与全市场批处理暂缓。

## Capabilities

### New Capabilities

- `structured-fact-materialization`: 将结构化记录物化为可消费的标准事实、维度和事件，并保留完整字段级血缘。
- `eight-step-analysis-pipeline`: 贯通四层研究流程、高层任务准备、按需知识、自主模型判断、确定性计算与人读报告。
- `ashare-universe-batch-processing`: 管理全 A 股证券目录、批量计划、失败恢复和逐证券结果汇总。

### Modified Capabilities

- `structured-acquisition-repair`: 增加已完成结构化运行可被事实物化和报告消费的契约；不改变既有采集状态、来源门禁和快照不变量。

## Impact

- 影响 `src/analysis/structured`、`src/analysis/formulas.py`、`src/analysis/reporting.py`、`src/analysis/service.py`、CLI/API 和前端数据展示。
- 复用现有 SQLite 结构化存储、共享快照、`FactRecord`/`ReportVersion` 和导出器，不创建第二套原始数据存储。
- 需要新增版本化配置和报告元数据；不会提交凭据、原始响应、数据库或生成报告。
- 严格历史模式只使用 `available_at` 不晚于截止时点的记录；当前研究允许供应商历史序列，但报告必须标注 point-in-time 限制。
- 后补字段解释分别记录原采集字段版本和新增映射版本；严格历史同时约束数据可得时间与解释合同生效时间，不能追溯伪造历史已知口径。
- 范围纠偏需要新增版本化研究范围并修改未来计划的默认选择，不重写已冻结 registry、run、原始缓存或物化哈希。旧运行的兼容回放不自动转化为新的全量采集或补采任务。
- 自动化测试、真实联网/缓存回放和人工黄金验收分别记录，任何一类通过都不代表另外两类完成。
- 既有 2.1、2.2 实现和七家公司导出作为技术草稿保留；规划状态回退不会改写已冻结轻量包、数据库、原始证据或历史报告版本，后续修复形成新版本并保留差异说明。

## Non-goals

- 不新增第二套来源注册、原始数据库、向量库或常驻模型服务；宿主 Codex／Claude Code 执行研究，框架不强制新增模型 Key。
- 不承诺全部公司、全部格式、所有资料都能取得；按研究问题记录来源、处理、阅读、计算和知识缺口。
- 不自动交易，不将主观假设混作历史事实；不以诺奖标签替代理论适用性。
- 不因本次规划修订声称业务代码已经符合新合同，不改写旧快照、原始文件或报告。

## Acceptance boundaries

数据正确、核心包可用、真实模型分析、图表排版和用户阅读分别验收。既有数值及导出证据保留，6.2–6.4重新打开，6.5记录用户拒绝当前人读成果；具体工作见[任务](tasks.md)。离线、真实缓存、联网和人工检查不可互相代替。范围、来源独立性、可得时间、修订和历史回放不变量沿用现有事实物化规格。
