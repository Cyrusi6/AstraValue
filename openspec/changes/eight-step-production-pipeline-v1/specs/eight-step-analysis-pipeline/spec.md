## Purpose

让八步研究从结构化事实、业务维度、治理事件和明确假设中生成可复算报告草稿，并逐题展示数据就绪、待补和不适用，避免缺失数据被叙事或评级掩盖。

## ADDED Requirements

### Requirement: 八步报告必须使用统一冻结输入
系统 MUST 为 ES01–ES08 生成固定顺序章节、置顶结论卡和审计附录；网页、Markdown、Excel、PDF 和 HTML MUST 由同一报告版本生成。每个确定性数字 MUST 引用事实 ID 或公式输入，不能只保留格式化后的数字。

#### Scenario: 完整普通企业输入
- **WHEN** 目标公司存在可消费财务事实、市场快照、行业路由和已确认假设
- **THEN** 系统生成八步报告及四种导出，核心数值和数据快照 ID 在各格式一致

#### Scenario: 财务输入缺失
- **WHEN** 关键指标缺少可消费事实或期间不完整
- **THEN** 对应问题和估值模型标为待补/失败，报告保留其余步骤，不输出伪造零值或目标价

### Requirement: 行业适用性和覆盖必须是三值状态
系统 MUST 根据已证实的行业画像选择普通企业、银行、保险、券商、地产、资源、公用事业或未盈利企业的适用模型；未知行业 MUST 不回退为通用企业。每道问题和每一步 MUST 分别给出 `ready`、`pending` 或 `not_applicable`，并列出缺失 requirement 和下一步补采路径。

#### Scenario: 银行公司
- **WHEN** 身份和行业画像证据将公司路由为银行
- **THEN** 报告可使用 PB/股利折现/剩余收益路径，并将通用企业 DCF 标为不适用

#### Scenario: 行业未知
- **WHEN** 行业证据不足或分类互相矛盾
- **THEN** 行业步骤和依赖行业模型保持待补，不自动使用普通企业模型关闭缺口

### Requirement: 评级和预测假设必须保持草稿与用户确认边界
系统 MUST 允许生成计算结果和跟踪指标，但用户未确认的预测、情景概率和评级 MUST 保持草稿或暂不评级；系统不得自动形成交易指令。

#### Scenario: 仅有历史事实
- **WHEN** 没有用户确认的未来增长、WACC 或终值假设
- **THEN** 系统展示历史分析和待确认情景，评级为暂不评级且估值注明失败或假设缺失
