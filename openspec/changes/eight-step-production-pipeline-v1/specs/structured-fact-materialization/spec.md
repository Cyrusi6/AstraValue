## Purpose

把已冻结的结构化采集记录整理为可进入八步报告的标准事实，同时保留原始快照、行键、字段路径、来源版本和可用时间，使每个数字都能从报告回溯到不可变响应。

## ADDED Requirements

### Requirement: 结构化记录必须可物化为带血缘事实
系统 MUST 读取已完成结构化运行中的有效记录和已登记字段映射，生成标准事实、维度事实或事件；每个可消费数值 MUST 包含真实来源、快照身份、行键、字段路径、单位、期间、`available_at` 和映射版本。未知字段 MUST 保留但不得进入公式输入。

#### Scenario: 有效供应商财务字段
- **WHEN** 当前选定研究范围内的记录字段具备已验证标准映射、数值、单位、报告期和有效快照
- **THEN** 系统生成 `供应商直采` 事实并能通过事实 ID 返回完整字段级 lineage

#### Scenario: 未知字段或缺定位
- **WHEN** 原始响应含未登记字段，或映射缺少单位、定义或快照定位
- **THEN** 字段仍被保存为不可消费状态，物化过程不丢弃原值、不生成可计算事实

### Requirement: 期间和数据性质不得被猜测
系统 MUST 区分流量、存量、比率、累计、单季和 TTM；资产负债表存量 MUST NOT 被相减或相加为期间流量，缺少相邻累计期间时 MUST 留缺口。供应商预测、标签、文本和公告计划 MUST NOT 进入实际财务计算。

#### Scenario: 累计值转换单季
- **WHEN** 同一合并口径存在相邻季度累计收入
- **THEN** 系统以明确公式版本生成单季值，并保留两个输入事实 ID

#### Scenario: 缺少季度输入
- **WHEN** 只有当前累计值而缺少所需上一累计季度
- **THEN** 系统不生成单季或 TTM 数字，并输出缺失原因

### Requirement: 物化结果必须可重复且历史不可变
同一运行、快照、映射版本和截止时点 MUST 产生字节稳定的物化结果；新响应或修订 MUST 追加新版本并保留旧事实。严格历史查询 MUST 排除 `available_at` 晚于截止时点的记录。

#### Scenario: 重放相同运行
- **WHEN** 对同一结构化运行重复物化
- **THEN** 事实 ID、数值、lineage 和输出哈希保持一致，且不新增网络请求

#### Scenario: 迟到修订
- **WHEN** 同一报告期出现较晚可用的新快照
- **THEN** 新事实标记版本关系，旧报告仍读取旧快照，新报告按截止时点选择合适版本

### Requirement: 后补字段解释必须有来源依据且独立版本化
系统 MUST 支持显式选择有证据依据的 BaoStock 字段解释版本，记录证据定位及 SHA256、适配的原冻结来源和字段版本、输出单位及倍率、期间与数据性质、解释生效时间。系统 MUST NOT 修改原运行上下文、原字段值、旧映射合同或快照来使新解释获得准入。无法核实的字段 MUST 保留可定位缺口。

#### Scenario: 新解释消费旧采集字段
- **WHEN** 调用方显式选择具有完整来源依据并适配原冻结字段版本的解释合同
- **THEN** 系统生成独立的新物化版本，lineage 同时保存原始字段版本和新增解释版本，未选择新解释的回放仍得到原结果与原哈希

#### Scenario: 截止时点早于解释生效
- **WHEN** 严格历史物化的截止时点早于后补解释的生效时间
- **THEN** 系统不使用该解释生成可消费历史数值，输出明确原因，不把当前核实的语义当作过去已知

### Requirement: 真实缓存必须形成可核验的非零事实
系统 MUST 提供不依赖手工修改源数据库的可复现入口，在已有真实 BaoStock 缓存上将具有已确认解释的有效数值转为非零标准事实。验收 MUST 包含各数据集、指标和期间的数量、样本原值与标准值的独立复算、完整 lineage、重复物化哈希以及源数据库/快照不变的证据。系统 MUST 同时报告未支持字段及原因，零准入或仅合成测试通过不能表示真实数据物化已打通。

#### Scenario: 有文档依据的市场与财务字段
- **WHEN** 真实缓存包含单位、定义和期间已有可靠证据的 BaoStock 数值字段
- **THEN** 显式解释入口输出非零事实与逐数据集覆盖，金额、比例、每股数值及存量分别按已登记语义处理，空值或停牌缺失不能转换为零

#### Scenario: 原缓存只读重复物化
- **WHEN** 在同一真实缓存和同一解释版本上重复运行
- **THEN** 数值、事实标识和结果哈希一致，原始数据库及快照未变，没有新增采集请求，并将该证据标记为缓存回放而非当前联网或人工验收

#### Scenario: 正式物化导出进入研究工作区和报告
- **WHEN** 已物化 baseline 与 incremental 输出正式事实文件及当前版本消费清单
- **THEN** 轻量包和 reporting bridge 直接读取正式文件，按清单选择事实和维度版本，保留增量未替换的历史数据；空运行不隐藏其他当前运行，历史归档不混入当前输入，原始文件、消费清单和来源指针均保留哈希绑定

#### Scenario: 物化文件或选中版本丢失
- **WHEN** 物化 manifest 声明的文件、事实版本或选中清单缺失
- **THEN** 系统返回可定位的物化输入错误，MUST NOT 把读取约定失配或文件丢失转换成全部业务输入待补

#### Scenario: 正式文件合同升级及旧目录混用
- **WHEN** 新物化导出与旧辅助文件位于同一目录，或代码升级了导出结构
- **THEN** 正式输入仅消费 manifest 声明且哈希匹配的产物；缓存绑定导出版本、解释/profile内容与截止时间并验证必需文件，旧目录遗留文件不得混入新事实

#### Scenario: 已采原始记录、事件与逐题覆盖进入工作区
- **WHEN** 验证成功的结构化页含白名单业务字段或正式事件
- **THEN** 受限记录投影保留快照、来源、可得时间与修订血缘，排除前置目录查询；逐题覆盖从选中事实及证据重建，原始文本与未解释数值不得作为研究已完成；正式事件原样可读、可引用并传至报告，既有完整空查询和未完成查询保留真实凭证

#### Scenario: 加工与报表解析生成派生快照
- **WHEN** 工作区为补充材料或完整报表创建候选快照
- **THEN** 系统核验并继承父包全部声明但未被有意替换的文件原始字节，重新绑定输出哈希；完整逐题覆盖、事件和其他附加产物不得因固定旧文件清单丢失

### Requirement: 默认采集和物化范围必须绑定八步研究用途
系统 MUST 从既有 ES01–ES08 问题、阅读要求和已确认计算确定所需数据，为每项字段或文本证据保存用途、来源、必要上下文、期间与粒度。新采集、新补采和默认物化 MUST 使用版本化研究范围；没有明确八步用途的数据 MUST NOT 因接口支持或缓存存在而默认进入请求或消费投影。开盘价、最高最低价、每日涨跌、成交量额和换手等普通日线字段 MUST 默认排除。估值辅助数据 MUST 单独说明用途和获取范围，不能自动扩展为完整日行情历史。

#### Scenario: 默认财报研究计划
- **WHEN** 用户按八步框架创建新的研究采集计划且未指定其他数据需求
- **THEN** 计划仅选择有八步用途的字段或证据，列出对应问题与期间；普通日线字段不进入请求或默认事实投影

#### Scenario: 估值需要市场输入
- **WHEN** 已登记估值计算需要分析时点价格、市值、股本或特定范围的历史估值序列
- **THEN** 系统只选择该用途需要的市场输入、日期及口径上下文，不因共用接口附带选择无关日线字段，不将单个价格用途扩展为全部价格历史

#### Scenario: 接口固定返回额外字段
- **WHEN** 为所需数据请求的接口无法只返回所选字段
- **THEN** 原始响应按既有快照规则保留，附带字段不自动进入消费投影，不计入八步业务覆盖；支持字段选择的接口在请求端收紧字段

#### Scenario: 本地采集时间与上游字段分离
- **WHEN** 系统为结构化响应记录本地采集时间 `__retrieved_at`
- **THEN** 该时间仅作为 provenance 保存，不进入上游请求列、业务字段投影、报告期间或上游内容版本哈希；没有已登记业务日期时保留缺失，旧快照和冻结记录保持不变

#### Scenario: 从旧缓存按明确窗口查询历史估值
- **WHEN** 研究指定历史估值日期窗口和参考倍数
- **THEN** 系统复用原缓存及正式字段准入，只投影所需PE、PB和收盘价，窗口进入独立合同哈希，不修改冻结运行或旧报告；分位注明窗口、观测数、非正PE排除数和算法，当前供应商历史序列不得冒充当时可得数据或预测PE

#### Scenario: 同行估值日期不同
- **WHEN** 研究请求多家公司的同日估值比较
- **THEN** 系统选择全部公司的共同有效日期，不以各自最新日或前值填充冒充同日；缺共同日期返回具体缺口，跨运行的冲突值不得静默覆盖

#### Scenario: 旧缓存兼容回放
- **WHEN** 调用方显式重放已冻结的历史运行与解释合同
- **THEN** 原有事实标识和哈希保持不变，该回放不启动新采集，也不将旧的全量字段范围自动沿用到后续计划或补采

### Requirement: 业务验收必须反映八步所需数据覆盖
系统 MUST 按公司、八步问题、所需字段或文本证据、期间报告覆盖、缺口和下一步获取路径。三表及附注、业务、治理、资本行为、行业和估值辅助输入 MUST 分别统计；尚未处理的要求 MUST 保留在覆盖分母中。行情行数、状态编码和纯技术字段 MUST NOT 代替财报数据覆盖。仅有物化技术测试或市场数据非零结果 MUST NOT 表述为八步财报数据层已经完成。

#### Scenario: 行情充足但财务输入缺失
- **WHEN** 缓存中有大量日线记录，但八步所需三表字段、经营证据或财务期间缺失
- **THEN** 对应问题仍显示待补并列出缺失输入，不因行情记录较多提高这些问题的覆盖率

#### Scenario: 报告期间口径未确认
- **WHEN** 财务字段只有报告期末证据，无法确认累计或单季口径
- **THEN** 原值和依据保留，依赖单季或 TTM 的问题继续显示口径缺口，不将已有数值视为该问题已满足

### Requirement: 文件选择必须绑定材料类别与研究用途
系统 MUST 按数据与文件采集清单 D01–D21 记录材料类别、问题 ID、来源、报告期或事件期间、语种及选择原因，区分必取、按需、仅目录和默认不取正文。所需完整中文年报、中报 MUST 保留完整原件及内部审计章节；摘要 MUST NOT 冒充完整报告或完整附注。季度正文、经营/治理/资本事件和行业材料 MUST 按研究问题、具体缺口或存续事项选择，不因目录存在而下载所有附件。

#### Scenario: 默认财报文件基线
- **WHEN** 使用原全量研究profile且公司在分析截止日已披露所需五个年度报告、最新中报和上年同期中报
- **THEN** 系统复用有效完整正文或安排取得缺少的原件，记录各报告身份和期间；其他中报及更早报告仅因已登记用途纳入，不生成上市前不存在的报告

#### Scenario: 只有摘要可得
- **WHEN** 所需完整报告不可得，但取得摘要中的有关数据
- **THEN** 系统标明临时摘要来源并保留完整报告/附注缺口，不把摘要解析成功记为完整正文完成

#### Scenario: 季报或会议材料有实质用途
- **WHEN** 季报需要解释重要变化或补结构化字段，或会议决议确认重要资本事项
- **THEN** 系统按对应问题选择必要正文并记录触发原因，不按“季度”或“会议”关键词一律排除；未选中的常规流程材料只保留目录，不记为下载失败

### Requirement: 停采正文必须准确区分独立文件与报告内章节
系统 MUST 延续独立审计 PDF（包括其附带报表及附注）和英文年报的默认正文停采策略，保留已发现目录和旧文件。系统 MUST NOT 因文件包含“审计”关键词而排除完整中文年报、一般募集资金使用报告、内控自我评价或引用审计结论的普通公告。文件类别判定 MUST 结合正式类型、主体、附件关系、语种与内容特征，不能仅依据扩展名。

#### Scenario: 中文年报包含审计章节
- **WHEN** 所需完整中文年报含审计报告和财务附注章节
- **THEN** 系统保留整份原件及这些章节，独立审计停采不删除或屏蔽报告内部内容

#### Scenario: 发现独立审计附件和英文年报
- **WHEN** 必要公告目录发现准确判型的独立审计 PDF 或英文年度报告
- **THEN** 新任务保留目录及选择依据而不请求其正文或解析服务，已有归档证据保持不变；该规则不自动扩展到其他英文材料或一般内控自评文件

### Requirement: 文件取得和解析不得冒充语义消费完成
系统 MUST 核对真实 MIME 与内容，保存原件 URL、哈希和版本，区分发现、选择、下载、解析、语义整理与可消费状态。PDF 事实 MUST 定位到页/表，HTML 到段落/表，官方表格到工作表/单元格或行列；派生文本、转换件和 OCR 结果 MUST 绑定原件及解析版本。接口 JSON 或 SDK 序列化结果 MUST 保留行键与字段路径并准确标注取得方式。未验证的 DOC/XLS/XBRL/ZIP 等来源或格式 MUST 输出具体适配缺口，不能因列入清单就声明已经支持。

#### Scenario: 下载成功但无法取得所需附注字段
- **WHEN** 文件已下载或解析文本已生成，而所需字段缺少单位、期间、表头或可核查定位
- **THEN** 对应输入仍显示语义或定位缺口，不进入确定性公式，不以下载/OCR 成功提升该问题的业务覆盖

#### Scenario: 必要材料格式尚无适配器
- **WHEN** 已登记问题需要的官方表格或附件包缺少已验证解析能力
- **THEN** 系统分别记录实际取得状态与格式适配缺口，不伪造表格值或把本系统导出文件当上游证据；已有有效原件及解析只按哈希和版本复用

### Requirement: 数据层增量与处理状态必须可独立核验
系统 MUST 复用已提交历史期间，只补缺失期间并刷新明确的最近期间；显式报告期 MUST 下推到适用请求。覆盖 MUST 保留法定披露窗口内的应需期间，不能因为未取得最新财报而缩短分母。系统 MUST 分开登记来源未取得、已有数据待语义处理、阅读待审、研究方法输入及尚未集成的计算路线，不得统称为供应商无数据。

#### Scenario: 增量已有多数期间
- **WHEN** 同公司同数据集已有成功提交的历史报告期
- **THEN** 新 EM-F 增量只查询缺失报告期及最新两期；相同运行重复执行不新增请求，跨运行覆盖保留旧期间并重新处理修订冲突

#### Scenario: 缺少最新财务记录
- **WHEN** 使用原全量研究profile且已过中报披露窗口但公司没有可消费中报事实
- **THEN** 十二季度覆盖仍包含应需中报期，系统显示对应缺口而不退回上一年度缩短要求

#### Scenario: 具备部分确定性指标
- **WHEN** 同主体、期间、来源与币种的完整事实能够进入已登记费用率或现金流公式
- **THEN** 系统输出带输入事实 ID 和公式版本的指标，金融企业不套普通企业公式；整条研究计算路线尚未接通时另行标记，不以已有指标关闭所有研究要求

#### Scenario: 原件发布过程中断
- **WHEN** 内容寻址路径存在与其 SHA256 不符的未完成原件
- **THEN** 系统保留该异常文件作为排障证据，并原子发布重新取得的正确 bytes；可用缓存通过哈希检查后复用

### Requirement: 轻量研究范围必须贯穿请求和消费
系统 MUST 支持独立版本化轻量profile，选择三年/八季度核心输入及必要计算前置期，并将profile传入计划、补采、正文选择、消费投影和缓存键。轻量默认正文 MUST 为最新完整中文年报及最新已披露中报，历史与事项正文按明确触发选择。旧全量合同和证据 MUST 保持不变，轻量入口 MUST NOT 静默复用全量补采范围。

#### Scenario: 核心缺口触发补采
- **WHEN** 全量覆盖中有大量缺口但轻量只激活指定字段和期间
- **THEN** 新请求只包含激活要求及其必要依赖，固定附带字段保留原快照而不进入默认消费，未触发的历史正文不下载

#### Scenario: 八季度内缺少最新披露
- **WHEN** 轻量窗口包含应披露但尚未取得的最新季度
- **THEN** 该季度仍在核心覆盖分母中，系统不按最新有值期间缩窗，也不修改原全量十二季度覆盖

### Requirement: 核心包必须紧凑可追溯且不掩盖风险
系统 MUST 从已有可消费事实与有定位原文构建业务、财务、质量风险、治理资本、行业驱动、估值约束六组核心输入，提供Markdown/JSON、核心覆盖、证据索引、下一步工作及可复现manifest。默认模型输入 MUST 有15,000 token预算和明确计数或估计方法。系统 MUST 保留关键数字口径、已知重大风险、冲突和核心缺口；核心必保信息超限时 MUST 返回budget_exceeded，不能静默截断后声称完整。

#### Scenario: 重要风险遇到预算限制
- **WHEN** 普通重复证据和已知重大风险同时竞争剩余输入预算
- **THEN** 系统先压缩重复/可选信息，保留风险与来源和缺口；仍不能满足预算时显式返回超限，并保存省略原因

#### Scenario: 原文检索与未核查事项
- **WHEN** 用户按核心包证据ID读取原文，或者某类风险尚未完成正文核查
- **THEN** 系统按实际页/表/字段返回有界内容和续页信息；未核查事项保持pending或source_text_available，不输出无风险结论

### Requirement: 轻量覆盖与验收必须独立于全量研究结论
系统 MUST 保留54题与全量要求的引用，并为轻量标明core/conditional/deferred范围路由及独立质量状态。首版 MUST 以七家白酒真实数据验收，未验证行业 MUST 明示限制，不能套用普通企业公式。默认构建 MUST 离线复用，真实补采、缓存复算、自动测试和人工验收 MUST 分栏保存。紧凑包不等于完整报告或模型研究评级。

#### Scenario: 范围外问题和金融公司
- **WHEN** 轻量未激活某问题或公司属于未验证金融画像
- **THEN** 系统保留其范围和质量状态及原因，不删除全量分母、不标为已回答或无依据的不适用，不调用通用企业公式

#### Scenario: 固定真实输入重复构建
- **WHEN** 相同profile、来源投影、解释版本和as_of重复构建核心包
- **THEN** 核心内容、引用和结果哈希一致且无网络，源库及原件未改变；输入更新形成新版本，原namespace和旧证据继续可追溯

### Requirement: 正式派生指标与估值基准必须由代码计算并区分约束性质
系统 MUST 从同口径原始事实按版本化公式计算并保存同比、CAGR、单季、TTM、利润率及适用杜邦等派生，记录输入、定义、单位、期间和版本；默认向模型提供结果和必要限制，完整推导可按需读取。硬性有效性条件 MUST 检查并在失败时拒绝依赖计算；历史及同行参考区间 MUST 与硬约束区分，不能静默裁剪模型预测。WACC等公式 MUST 由代码执行，参数依据仍由模型或显式规则选择，不隐藏主观选择。

#### Scenario: 输入缺失或公式无定义
- **WHEN** 正式计算缺必要期间、分母为零、口径冲突，或稳定增长永续折现率不大于永续增长率
- **THEN** 该计算返回具体失败原因而非数值，其他独立计算继续；失败不通过模型手算或绘图脚本绕过

#### Scenario: 假设超出历史参考区间
- **WHEN** 模型明确说明未来利润率超出历史区间的依据且满足硬性数学及口径条件
- **THEN** 代码保留原假设计算结果及敏感性，显示参考差异，不静默裁剪为历史最大值，不将假设作为已观察事实
