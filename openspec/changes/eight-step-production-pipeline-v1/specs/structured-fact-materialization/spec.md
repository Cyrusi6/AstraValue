## Purpose

把已冻结的结构化采集记录整理为可进入八步报告的标准事实，同时保留原始快照、行键、字段路径、来源版本和可用时间，使每个数字都能从报告回溯到不可变响应。

## ADDED Requirements

### Requirement: 结构化记录必须可物化为带血缘事实
系统 MUST 读取已完成结构化运行中的有效记录和已登记字段映射，生成标准事实、维度事实或事件；每个可消费数值 MUST 包含真实来源、快照身份、行键、字段路径、单位、期间、`available_at` 和映射版本。未知字段 MUST 保留但不得进入公式输入。

#### Scenario: 有效供应商财务字段
- **WHEN** 当前选定研究范围内的记录字段具备已验证标准映射、数值、单位、报告期和有效快照
- **THEN** 系统生成 `供应商直采` 事实并能通过事实 ID 返回完整字段级 lineage

#### Scenario: 未知字段或缺定位
- **WHEN** 原始响应含未登记字段，或映射缺少单位、定义或快照定位
- **THEN** 字段仍被保存为不可消费状态，物化过程不丢弃原值、不生成可计算事实

### Requirement: 期间和数据性质不得被猜测
系统 MUST 区分流量、存量、比率、累计、单季和 TTM；资产负债表存量 MUST NOT 被相减或相加为期间流量，缺少相邻累计期间时 MUST 留缺口。供应商预测、标签、文本和公告计划 MUST NOT 进入实际财务计算。

#### Scenario: 累计值转换单季
- **WHEN** 同一合并口径存在相邻季度累计收入
- **THEN** 系统以明确公式版本生成单季值，并保留两个输入事实 ID

#### Scenario: 缺少季度输入
- **WHEN** 只有当前累计值而缺少所需上一累计季度
- **THEN** 系统不生成单季或 TTM 数字，并输出缺失原因

### Requirement: 物化结果必须可重复且历史不可变
同一运行、快照、映射版本和截止时点 MUST 产生字节稳定的物化结果；新响应或修订 MUST 追加新版本并保留旧事实。严格历史查询 MUST 排除 `available_at` 晚于截止时点的记录。

#### Scenario: 重放相同运行
- **WHEN** 对同一结构化运行重复物化
- **THEN** 事实 ID、数值、lineage 和输出哈希保持一致，且不新增网络请求

#### Scenario: 迟到修订
- **WHEN** 同一报告期出现较晚可用的新快照
- **THEN** 新事实标记版本关系，旧报告仍读取旧快照，新报告按截止时点选择合适版本

### Requirement: 后补字段解释必须有来源依据且独立版本化
系统 MUST 支持显式选择有证据依据的 BaoStock 字段解释版本，记录证据定位及 SHA256、适配的原冻结来源和字段版本、输出单位及倍率、期间与数据性质、解释生效时间。系统 MUST NOT 修改原运行上下文、原字段值、旧映射合同或快照来使新解释获得准入。无法核实的字段 MUST 保留可定位缺口。

#### Scenario: 新解释消费旧采集字段
- **WHEN** 调用方显式选择具有完整来源依据并适配原冻结字段版本的解释合同
- **THEN** 系统生成独立的新物化版本，lineage 同时保存原始字段版本和新增解释版本，未选择新解释的回放仍得到原结果与原哈希

#### Scenario: 截止时点早于解释生效
- **WHEN** 严格历史物化的截止时点早于后补解释的生效时间
- **THEN** 系统不使用该解释生成可消费历史数值，输出明确原因，不把当前核实的语义当作过去已知

### Requirement: 真实缓存必须形成可核验的非零事实
系统 MUST 提供不依赖手工修改源数据库的可复现入口，在已有真实 BaoStock 缓存上将具有已确认解释的有效数值转为非零标准事实。验收 MUST 包含各数据集、指标和期间的数量、样本原值与标准值的独立复算、完整 lineage、重复物化哈希以及源数据库/快照不变的证据。系统 MUST 同时报告未支持字段及原因，零准入或仅合成测试通过不能表示真实数据物化已打通。

#### Scenario: 有文档依据的市场与财务字段
- **WHEN** 真实缓存包含单位、定义和期间已有可靠证据的 BaoStock 数值字段
- **THEN** 显式解释入口输出非零事实与逐数据集覆盖，金额、比例、每股数值及存量分别按已登记语义处理，空值或停牌缺失不能转换为零

#### Scenario: 原缓存只读重复物化
- **WHEN** 在同一真实缓存和同一解释版本上重复运行
- **THEN** 数值、事实标识和结果哈希一致，原始数据库及快照未变，没有新增采集请求，并将该证据标记为缓存回放而非当前联网或人工验收

### Requirement: 默认采集和物化范围必须绑定八步研究用途
系统 MUST 从既有 ES01–ES08 问题、阅读要求和已确认计算确定所需数据，为每项字段或文本证据保存用途、来源、必要上下文、期间与粒度。新采集、新补采和默认物化 MUST 使用版本化研究范围；没有明确八步用途的数据 MUST NOT 因接口支持或缓存存在而默认进入请求或消费投影。开盘价、最高最低价、每日涨跌、成交量额和换手等普通日线字段 MUST 默认排除。估值辅助数据 MUST 单独说明用途和获取范围，不能自动扩展为完整日行情历史。

#### Scenario: 默认财报研究计划
- **WHEN** 用户按八步框架创建新的研究采集计划且未指定其他数据需求
- **THEN** 计划仅选择有八步用途的字段或证据，列出对应问题与期间；普通日线字段不进入请求或默认事实投影

#### Scenario: 估值需要市场输入
- **WHEN** 已登记估值计算需要分析时点价格、市值、股本或特定范围的历史估值序列
- **THEN** 系统只选择该用途需要的市场输入、日期及口径上下文，不因共用接口附带选择无关日线字段，不将单个价格用途扩展为全部价格历史

#### Scenario: 接口固定返回额外字段
- **WHEN** 为所需数据请求的接口无法只返回所选字段
- **THEN** 原始响应按既有快照规则保留，附带字段不自动进入消费投影，不计入八步业务覆盖；支持字段选择的接口在请求端收紧字段

#### Scenario: 旧缓存兼容回放
- **WHEN** 调用方显式重放已冻结的历史运行与解释合同
- **THEN** 原有事实标识和哈希保持不变，该回放不启动新采集，也不将旧的全量字段范围自动沿用到后续计划或补采

### Requirement: 业务验收必须反映八步所需数据覆盖
系统 MUST 按公司、八步问题、所需字段或文本证据、期间报告覆盖、缺口和下一步获取路径。三表及附注、业务、治理、资本行为、行业和估值辅助输入 MUST 分别统计；尚未处理的要求 MUST 保留在覆盖分母中。行情行数、状态编码和纯技术字段 MUST NOT 代替财报数据覆盖。仅有物化技术测试或市场数据非零结果 MUST NOT 表述为八步财报数据层已经完成。

#### Scenario: 行情充足但财务输入缺失
- **WHEN** 缓存中有大量日线记录，但八步所需三表字段、经营证据或财务期间缺失
- **THEN** 对应问题仍显示待补并列出缺失输入，不因行情记录较多提高这些问题的覆盖率

#### Scenario: 报告期间口径未确认
- **WHEN** 财务字段只有报告期末证据，无法确认累计或单季口径
- **THEN** 原值和依据保留，依赖单季或 TTM 的问题继续显示口径缺口，不将已有数值视为该问题已满足
