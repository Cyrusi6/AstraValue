## Context

历史架构基线：结构化运行已经把共享 acquisition 控制面、原始响应快照、页面、记录和字段映射写入同一 SQLite namespace；`ReportStorage` 已有 `FactRecord`、维度事实、事件、报告和导出能力。物化和轻量包现已接通；当前缺口是框架高层准备、按需知识和模型自主研究到人读报告的闭环。

## Goals / Non-Goals

**Goals:**

- 用结构化字段表和冻结上下文生成可消费事实，建立明确的 source/snapshot/row/field lineage。
- 复用已有公式、行业路由、覆盖评估、报告和导出，不重复实现财务计算。
- 提供单证券和全 A 股批量的幂等 CLI/API，失败可恢复并留下可查询状态。
- 以既有八步问题所需数据为采集和物化范围，先取得逐问题的真实覆盖与缺口，再接入报告和批处理。
- 先将贵州茅台固化为单证券黄金报告：可读表格的期间和单位正确，结构化事实、定位原文、治理资本记录、同行及行业证据进入相应报告对象，八步状态和缺口与实际内容一致。

**Non-Goals:**

- 不修改供应商协议、来源门禁、repair attempt 上限或历史快照。
- 按当前研究问题补充必要知识条目，不把骨架方法当成完成，不要求填完全部教材。
- 不自动启动全市场长时间联网任务；生产运行由操作者显式触发。
- 不把贵州茅台黄金样本直接外推为全部股票已通过；其他白酒在黄金门后复用同一普通企业/白酒链路验证，金融及其他特殊行业仍需独立画像和代表性样本。

## Decisions

1. **物化层放在 `structured` 域并调用现有 `ReportStorage`。** 结构化表仍是原始和字段证据的权威，标准 `FactRecord` 是报告消费投影；通过稳定哈希生成事实 ID，重复物化幂等。备选是在 SQL 中直接拼装报告，因无法复用现有模型校验和导出而放弃。

2. **只把具有可核实字段合同且质量通过的数值映射为可消费事实。** 原始未知字段仍保留在结构化记录中，定义、单位、数据性质或定位缺失时生成缺口而不是猜测。已冻结旧合同的解释结果不变；需要补齐历史缓存语义时，调用方显式选择新增版本的解释合同，记录其证据和适配的原来源/字段版本，不覆盖旧 `FieldRule` 或旧记录。

3. **期间整理使用现有 `derive_single_quarter`/`derive_ttm` 和显式公式版本。** 存量、比率和公告/预测类字段走独立分类；缺输入直接返回缺口。避免把累计或存量误当流量。

4. **研究输入与模型成果分离。** 框架以公司、截止日和范围启动任务，在内部解析唯一身份、来源投影、缓存、补采和处理依赖，复用既有 runtime/storage。新增高层 prepare/resume/status 语义与按问题补采、计算接口；具体子命令随 CLI 实施确定，当前不能作为已实现命令宣传。模型只接收任务标识、核心包和可操作的缺口，身份确有歧义才询问用户。单次网络执行有请求/时间上限，但不设置压缩整体研究的总耗时门，持久化 checkpoint，不把网络失败交给模型逐个调接口。旧 lite/evidence 等低层命令保留兼容。

   模型提交正文、判断、引用、假设和图表意图；代码仅校验和组装。请求记录提出者、包版本、假设理由、计算输入和结果、引用及条件；ReportCreateRequest/ReportVersion 通过版本化扩展接收这些成果。旧规则生成 ClaimRecord 仅作为观察草稿，不得自动认定已经研究完成。Agent 输出未到达时返回 analysis_pending，不自动生成固定结论补位。

5. **全 A 股使用持久化批次清单而不是一次性线程池。** 目录身份与每个证券状态独立记录，批次只调度有唯一身份且明确启用的数据集；重试和并发沿用已有租约/来源门，后续可追加持久 job 而不改变单证券合同。

6. **后补解释是独立版本的消费投影。** BaoStock 映射须逐字段绑定官方文档或供应商源代码的定位和 SHA256，明示单位倍率、期间、数据性质、复权以及适配的原冻结登记。物化记录同时包含原始字段版本与新增解释版本，严格历史模式按数据观察时间和解释生效时间共同过滤。解释变更不能修改原始数据库或冒充过去已完成核验。

7. **真实非零结果是事实物化补全的验收条件。** 在现有真实缓存上重复运行，核验各数据集和指标数量、样本原值到标准值的计算、lineage 和稳定哈希；仅得到零准入缺口或只通过 MockTransport 样本不能满足该条件。未证明语义的字段继续缺口。原缓存保持只读；需要落地复现输出时使用独立输出文件并保留源绑定，不能复制重绑或修改源快照来通过验收。

8. **2026-09-13 的范围纠偏以研究用途为准。** 复用既有 ES01–ES08 需求及阅读规则，为每项数据登记具体问题或计算用途、字段/证据类型、必要上下文、期间与粒度。普通开盘、最高最低、涨跌幅、成交量额、换手等日线字段默认排除；收盘价等市场输入只有在指定时点估值对比或其他已登记研究用途需要时才进入范围，不默认取得全部历史。历史估值分位仍须有明确估值需求、序列口径和计算范围，不能据此附带取得无关日线字段。数据范围不能仅按供应商或接口整体判断。

9. **范围约束同时作用于请求与消费。** 接口支持字段选择时只请求所需字段及身份、日期等必要上下文；固定返回的附带字段可随原快照保留，但不自动扩展为消费事实或业务覆盖。新计划、补采与默认物化冻结新的研究范围版本；不改变旧登记或解释合同的同版本内容，不把旧任务的全量字段直接沿用到新采集。范围选择不能绕过来源、namespace、可得时间和字段解释准入。

10. **技术验收与业务覆盖分别记录。** 1.1–1.7 的完成说明物化实现及旧缓存可复算，不说明八步所需数据完整。业务进度按公司、八步问题、财报字段或文本证据、所需期间展开，分列已具备、缺失和有证据的不适用项；未处理的要求也进入覆盖分母。优先核对三表与财务附注，再按实际缺口安排业务、治理、资本行为、行业及估值输入；不能用行情、标签或状态编码的条数冲抵这些缺口。

11. **文件类别和文件格式分别登记。** [采集清单](../../../docs/acquisition/eight-step-data-and-document-scope.md) 的 D01–D21 表达业务材料类别及用途，PDF/HTML/JSON/官方表格等表达载体，不能仅按后缀或标题关键词选择。五份完整中文年报、最新及上年同期中报构成默认文件基线；季度正文、其他中报、经营/治理/资本及行业资料按问题、缺口或存续事项选择。摘要不证明全文或完整附注已取得。保留中文年报内部审计章节，独立审计 PDF 与英文年报沿用精确停采规则。

12. **目录、正文、解析和事实是不同层次。** 冻结选择原因、问题 ID、文件类别与格式、来源 URL、报告期、语种、哈希和解析版本；PDF 定位到页/表，HTML 到段落/表，官方表格到工作表及单元格。正文未选中、下载失败、解析失败、解析后字段缺失和可消费分别表达；摘要、OCR 或下载成功不冲抵语义缺口。DOC/XLS/XBRL/ZIP 等列入需求不表示已有已验收适配器，必要能力另行验证。旧目录、原件、解析和合同哈希不改写。

13. **期间和单位先于内容生成通过黄金校验。** 人读表格的索引必须包含 `metric_id + period_end + period_type`，同一年末的累计值和第四季度单季值不得互相覆盖；比例、每股值、金额和估值倍数分别按登记语义格式化，PE/PB/PS/EV 倍数不得使用百分比格式。先在贵州茅台上对原值、标准值、年度与季度恒等关系和最终显示值做独立复算，再允许进入报告写作。

14. **贵州茅台是关闭 2.1、2.2 的前置黄金门。** 既有七份导出只作为 QA 草稿。贵州茅台的新报告必须逐章具有证据化分析或明确待补原因，54题、`missing_items`、证据完整度、模型输入和估值失败原因彼此一致；Markdown、HTML、Excel、PDF 和冻结 JSON 共享同一报告版本与事实引用。自动测试、渲染检查和用户人工阅读三门均通过后，才可将同一代码复用于其余六家白酒。

15. **黄金样本不等于全市场证明。** 贵州茅台通过证明普通企业/白酒画像、上交所单证券和当前来源组合的公共主链路；其他交易所、披露差异和特殊行业通过参数化范围与行业路由处理，并分别保留代表性验收。批量能力不能仅替换公司名称，必须使用证券代码、市场、有效期和行业画像解析身份。

16. **知识按问题检索，非强制阅读。** 复用 docs/methodology 和 config/methods；知识索引返回题名、出处、状态、适用问题及有界摘要，正文按需读取。新增条目保存作者、版本、原始出处和页／章节、适用前提、限制、反例，与可执行公式分开。没有匹配项返回 knowledge_gap，不返回 skeleton 充数。首批服务于盈利质量、竞争优势和适用估值问题；不批量扩写37个骨架。经典和诺奖相关理论按问题选择，宿主模型也可不查知识库直接推理。

17. **估值假设由模型提出，算术由代码执行。** 保存事实／推断／假设的不同角色；模型决定适用方法、预测参数、理由与范围，调用现有公式完成情景和关键参数敏感性，再解释方法差异，给出价值区间和评级及改变判断的条件。用户修改是可选覆盖，不是准入门。必要输入缺失只阻塞依赖它的计算和结论；泛泛“需要进一步分析”不能替代已经可作出的判断。

18. **图表和正文共享冻结数据。** 模型提出图表用途；代码从同一报告版本的事实和计算结果生成收入利润折线、利润现金流柱图及适用的估值敏感性图，禁止手绘数据或各导出器独立算数。正文短引用指向附录；大表、内部状态、完整ID和血缘移入附录。缺期间不能以零补图；图上标明期间、单位和必要来源。Excel 继续保留查数与公式功能。模型逐页检查渲染后的最终研报，修复截断、溢出、重复段落及图文矛盾；自动像素/非空检查不能代替阅读。

19. **状态分别回答数据与研究问题。** 任务返回 acquisition、processing、analysis、rendering 状态；缺口区分 acquisition、parsing、semantic_processing、document_reading、calculation、research_context/knowledge。按事实覆盖、问题完成和报告质量分别统计；展开明细可以有多个依赖，用户摘要按实际缺失资料和受影响判断去重，不能把1518条任务称为1518份缺失文件，不能用单个0%描述全部成果。

20. **MCP薄适配复用服务。** 首先补齐research域的高层任务与查询服务，再用MCP暴露研究动作；保留CLI用于复现，不给MCP复制第二套采集/计算实现。prepare_research接受company/as_of/scope，latest在启动时解析；get_task以持久task_id查询或通过明确恢复动作推进，读取状态不隐式重复创建任务。query_research/request_materials使用结构化topic/period加question，未知topic返回明确能力缺口。工具结果统一包含research_id/snapshot_id、分层状态、可读正文或小表、去重缺口、短引用、下一步动作及分页信息；大对象按需读取，不只返回模型无法消费的文件路径。

21. **研究状态和草稿均可恢复。** 单次工具有运行上限、失败原因和检查点；同任务恢复不重复已完成请求。research_id绑定快照，补采生成新快照与变化摘要，模型显式采用并重审受影响判断，旧报告仍读旧版本。草稿按章保存Markdown、假设、判断与引用，修订追加版本。build_report接收草稿及图表引用，替换关键财务数值引用、生成标准内容对象/HTML/PDF；Excel侧重复计算禁止，兼容已有公式查看功能。新增元数据和状态采用追加兼容迁移。回滚可停用MCP及新版本入口，CLI、旧报告与原库继续可用。

22. **绘图与探索计算隔离。** 常规图目录可惰性渲染；常规和定制共享图表对象（ID、图片、底层数据、快照、来源、代码/模板版本及检查）。绘图沙盒仅使用只读选定数据，禁网络、禁止写事实库，限制文件范围、时间/内存和输出体积；Python允许展示性变换，但正式财务计算引用calculate结果。新算法走独立exploratory记录，经过定义与单位/期间核验、独立参考复算、适用/边界测试及重复执行才能用于正式报告，仍标注探索性质。未通过检查可保存探索材料但不能作为正式估值或评级数值依据。反复使用的算法通过规则版本、来源/方法说明和回归后才晋升处理层，不能从沙盒自动注册。

23. **知识卡可检索且轻量。** Markdown卡片四部分及出处元数据按计划.md，800—1500字仅建议；catalog首层是类别/短简介，库增大后分类和分页，search_knowledge返回少量条目，按条目ID继续读正文。索引输出与正文状态一致；ROIC等触发阈值需出处和口径，不硬编码成普适评级。金融公式留config/methods及实现，知识卡链接公式版本，不复制第二份计算真值。

24. **研究停止由结论需要决定。** 不给标准报告设总耗时完成门；初次覆盖选定核心范围，后续每项深入登记受影响结论、潜在改变机制和资料用途。无实质影响的扩展不进入默认任务；已具备完成判断的证据且无实质待查项时定稿。执行超限是checkpointed/可恢复，重复同因失败按来源门禁停重试并保留缺口，不靠换新任务绕过。持久任务使会话重启可续做，不承诺MCP调用之外宿主自动后台运行。

25. **成品读取是接口行为。** 返回报告文件，同时提供宿主可消费的页面图像或等效可视读取入口，以及引用/数据检查结果。模型需要看实际图表和页面，不能仅验证HTML DOM或文件存在。Codex和Claude Code分别记录真实调用、草稿恢复、绘图和成品查看验收；一个宿主通过不替另一个勾选。自动数值校验、人读质量和方法可靠性分开验证。

## Risks / Trade-offs

- [来源历史字段定义仍有缺口] → 旧合同维持原准入范围；根据逐字段来源依据新增解释版本，不把现有 31 个公式字段的数量当作真实数据可用证明，未核实字段继续明确待补。
- [供应商历史序列未必具备历史发布时间] → 当前研究可用但标记 PIT 限制；严格历史只按 `available_at` 过滤。
- [全 A 股运行量大且容易触发来源限制] → 默认批量为计划/有界单轮，显式保存 checkpoint，不在启动应用时自动联网。
- [行业方法仍是 skeleton] → 按需建设有出处知识条目，模型可选择其他有依据的适用方法；方法骨架不作引用证据，不因此禁止全部自主研究。
- [现有人读轻量包把年末单季覆盖年度累计，并把估值倍数显示为百分比] → 在贵州茅台黄金门中按 `period_type` 分键并按指标语义格式化，对七家公司既有文件只保留 QA 身份，不沿用为基线答案。
- [导出文件可打开掩盖分析对象为空] → 把非空且有引用的 `ClaimRecord`、适用的事件/同行/行业对象、覆盖与缺口一致性以及用户阅读签署列为独立门禁；`claims=0`、默认占位文字或 `evidence_completeness=1.0` 与54题全 pending 并存时必须失败。

## Migration Plan

先新增无破坏性的物化投影和 batch 状态表；旧 CLI/API、旧报告和旧结构化 run 保持可读。既有报告导出版本继续保留但标记为黄金门前 QA 草稿，不覆盖或删除。后续只对贵州茅台生成新版本，完成数据口径、语义对象、覆盖状态、四格式与人工阅读验收；失败时停止在贵州茅台并保留差异，不重生成其他公司。回滚只需停止调用新入口并保留追加表和事实投影，不删除任何原始快照。

BaoStock 后补解释采用显式版本选择，未选择时保留旧物化行为和哈希；新入口必须可直接复现，不依赖手工编辑数据库或构造运行上下文。新增解释的投影与旧投影分别保留，撤回新增解释仅影响后续消费选择。
